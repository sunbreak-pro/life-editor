# 判断の聞き方と置き場

ユーザー判断が必要になっても、待ちで作業を止めません。聞き方は作業の種類で分かれます。対話のチャットは、最後の報告のあとに AskUserQuestion（選択式の質問を出すツール）でまとめて聞きます。無人の実行（定時に動く作業）は質問を出せないので、判断待ちの置き場 `.claude/comm/decisions/chat-<self>.md` にエントリを書いて次の作業へ進みます（形式は decisions/README.md）。

まず [`decisions/POLICY.md`](../comm/decisions/POLICY.md) を確認します。該当する恒久裁定があれば、聞かずにそれに従います。

## 対話のチャット

- 判断が要る点で止まらず、自分で仮定を置いて進めます。置いた仮定と、決めてもらう点は、最後の報告に書きます。
- 聞くのは、最後の報告のあとです。推奨の選択肢を先頭に置き、質問文に「何が起きているか」と「なぜ決める必要があるか」を書きます。各選択肢の説明には、選ぶと起きることを書きます。
- 聞くのは「選択肢に割れる判断」だけです。不可逆操作（データ削除・本番設定の変更・履歴の書き換え・force 系の git）は、方針「不可逆操作は必ず同期で確認」（[`POLICY.md`](../comm/decisions/POLICY.md)）に従い、実行の直前にその場で聞きます。
- 実装中に計画外の変更が浮上したら、方針「実装中スコープ凍結」（[`POLICY.md`](../comm/decisions/POLICY.md)）に従います。実装せず、現計画を続けて、報告のあとに聞きます。Scope と AC の自己免除はしません。

## 無人の実行

- AskUserQuestion が使えないので、判断が割れる点は置き場にエントリで書き、その作業は保留して次へ進みます。`.claude/` に書けない実行は、報告の末尾の「判断キュー行き」節に書きます（`automation/routine-night.md`）。
- 実装中に計画外の変更が浮上したら、実装しません。置き場に書いて、現計画を続けます。Scope と AC の自己免除はしません（方針「実装中スコープ凍結」）。
- エントリの「放置時」は必ず安全側（保留・別作業へ）にします。無回答で作業が勝手に進む設計にしません。
- 不可逆操作は、置き場に書かず、保留して報告します。

## 回答を処理する

対話のチャットと無人の実行の、どちらにも当てはまります。実際には、無人の実行が積んだ判断を、次の朝に main のチャットが処理することが多いです（`automation/routine-night.md`）。

- セッション開始時に `decisions/ANSWERS.md` を確認し、自分宛の回答が残っていれば、新しい作業より先に消化します。
- **回答が付いたら、消す前に台帳へ昇格します。** `.claude/decisions/` にファイルを作り（置き場の本文をそのまま貼る）、置き場から削除します。INDEX の再生成は要りません。git 非追跡の派生ビューで、SessionStart hook が作り直すためです。手順の元になる文書は `.claude/decisions/README.md` です。
