# 画面が変わる計画は、デザインシステムと試作で UI / UX を確かめてから書く

> 2026-10-28 こうだいさんの決定（[`D-20261028-main-1`](../decisions/D-20261028-main-1.md)・#2372）。計画書に書く欄は [`_TEMPLATE.md`](../docs/vision/plans/_TEMPLATE.md) の「UI / UX の確認」節。

新しい機能と、見た目や操作の流れが変わる改修は、実装に入る前に画面の案を試作の中に作り、こうだいさんが確かめてから計画書を確定します。文字だけの計画書では、出来上がった画面が思っていたものと違うと実装のあとで分かり、作り直しになるためです。

## 対象

- **対象**: 新しい機能、画面・パネル・部品の追加、見た目や操作の流れが変わる改修。
- **対象外**: 見た目の変わらないバグ修正、リファクタ、docs、MCP の道具のように画面を持たない変更、1 画面の数 px のずれを直すだけの修正。

## 使うもの

- **デザインシステム**: Artifact の「Life Editor」（https://claude.ai/artifact/KPdEWuLhoeL9MdzRRa43Aa）。色・文字・余白・部品・文言の決まりはここに従います。値の正本はコードの `shared/src/styles/tokens.css` なので、食い違ったらコードを優先し、ずれを報告に書きます。
- **案を書き込む場所**: Claude Design の再現プロジェクト「Life Editor試作完成」の `Life Editor.dc.html`（https://claude.ai/design/p/90a82a78-0ef6-419a-80dd-0739acaa9df9?file=Life+Editor.dc.html&via=share）。今の画面の外枠と操作をほぼそのまま写した、動く試作です。新しい画布にゼロから描くより、今の画面と同じ外枠のまま見比べられるので、案はここに足します（2026-10-28 こうだいさんの指示）。単独の Claude Design は 2026-12-14 に Artifact へ移るので、移ったあとは移行先の Artifact に読み替えます。

## 手順

1. **デザインシステムと試作を読む**: デザインシステムは `Artifact` ツールの `read` で読みます。部品の説明は `project/README.md` と `project/components/*/README.md` にあります。試作は Artifact ツールでも DesignSync でも読み書きできないので、Chrome（claude-in-chrome）で開き、該当の画面を撮って今の UI を確かめます。
2. **試作のチャットに案を頼む**: Chrome から試作プロジェクトのチャットに依頼を送ります。依頼には次を入れます。
   - `Life Editor.dc.html` は変えず、複製したファイルに案を入れること。試作パネルに「今の形 / 案 A / 案 B」の切り替えを足し、対象の画面だけが切り替わるようにすること。
   - 今の形で困っていること、両案で削らない機能の一覧（コードから洗い出す）、各案の Desktop と Mobile（768px 未満）の配置。
   - 4 つの状態（読み込み中・空・エラー・通常）と、操作の途中の画面（追加・編集中・ドラッグ中など）。
   - 案が割れるときは 2〜3 案。違いを 1 行ずつ添えます。

   チャット欄は ProseMirror なので、文面は `document.execCommand('insertText', …)` で入れます。貼り付けのイベントを送ると添付ファイルとして二重に入るので使いません。

3. **こうだいさんに確かめてもらう**（👀 の Gate）: 試作の URL と、どのファイルのどの切り替えで見るかを渡し、どの案にするかと直すところを聞きます。直しも同じチャットに頼みます。返事を待つあいだは、計画書の画面に関わらない部分か、別の作業を進めます。
4. **計画書を書く**: 採った案の場所（試作の URL・ファイル名・切り替えの名前）・こうだいさんの返事を「UI / UX の確認」節に書き、採らなかった案を「検討した代替案」の表に書きます。Scope と Steps は採った案をもとに決めます。
5. **実装する**: 計画書が確定してから実装に入ります。実装中に案と違う画面にしたくなったら、自分で決めずに P-008 に従って判断キューへ出します。

## 補足

- 実装した画面は、merge のあとに chat-main が実ブラウザで撮り、採った案と比べます（`design-critique` スキル）。dev server と実ブラウザは chat-main だけが使います（CLAUDE.md §7.4）。試作のチャットへの依頼は Chrome を使うので、chat-main が行います。
- 値をコードへ戻すときの読み替え（px と Tailwind・`lumen-*` の対応）は [`docs/design/README.md`](../docs/design/README.md) の「調整した案を実装へ戻す手順」に従います。
