## D-20260802-settings-1: briefing の見出し serif を Settings のフォント設定にどこまで追従させるか（#556）

**背景**: #556 でフォント統一を実装。本文（AI 講評・宣言入力・宣言読み返し）は Settings のフォント選択に追従するよう統一済み。一方、新聞アイデンティティ（#269）を担う 3 箇所 — 題字 2 つ（`BriefingView.tsx` / `EveningView.tsx` のマストヘッド h2）と焦点行（`BriefingView.tsx` の「本日の焦点」）— は serif 固定のまま残している。Issue の要件「どこまで追従させるかは案を出してユーザー確認」に基づく判断待ち。なお Settings で「明朝（セリフ）」を選べば、固定箇所も本文も同じ serif スタックになる（#556 で選択肢のスタックを briefing の実フォントに一致させた）。

**A（現 PR の実装）: 題字 + 焦点行は serif 固定、本文のみ追従**（推奨 — 新聞の顔を保ちつつ本文は全画面統一。システムフォント選択時も briefing が「新聞」に見え続ける）

- 利点: 変更が最小で、briefing の視覚アイデンティティが設定に依存しない
- 欠点: 「アプリ全体を完全に 1 フォントへ」を求める場合、briefing だけ 3 箇所 serif が残る

**B: 題字のみ serif 固定、焦点行は追従**

- 利点: 固定を「題字 = ロゴ扱い」の 2 箇所だけに絞れる。焦点はユーザーの入力内容なので本文扱いという整理も立つ
- 欠点: 焦点行の見出しらしい風格（text-xl serif）がシステムフォント時に失われる

**C: 見出しも追従（briefing 内の font-serif 全廃・完全統一）**

- 利点: 例外ゼロ。Settings の選択がそのまま全要素に効く
- 欠点: システムフォント選択時に新聞アイデンティティ（#269）がほぼ消える

**放置時**: A のまま（現 PR の実装を維持。B / C の回答が来たら follow-up の小差分で対応 — 該当クラスの削除のみで戻せる）。

**期限感**: いつでも（#556 の merge 判断とは独立）。
