# 事前決裁ポリシー（POLICY）

「聞かなくていいこと」を増やすための恒久裁定集。判断に迷ったらまずここ → 該当なしなら decision キューへ。
**追加・変更はこうだいさんの明示承認のみ**（Claude が自分で裁定を足さない）。

- **P-001** merge と main への取り込みは、こうだいさんが行うか、こうだいさんが chat-main で `merge-round` スキルを起動したときだけ行う。スキルが merge するのは、その回の事前確認を通った PR だけにする。作業レーンは merge しない。人の起動なしに merge が走る仕組み（定時実行・無人ループ）は作らない（2026-11-02 改定 = D-20261102-main-1）。例外: `issue-workflow` の起動前の確認でこうだいさんが「merge-round まで回す」を選んだ実行では、サブエージェント `work-finishers` がその実行の PR に限って `merge-round` を回す。この選択を人の起動に数え、chat-main が `.git/merge-round/finisher-approved.json` に印を書く（2026-11-08 のこうだいさんの依頼による。この例外を入れる PR の merge を明示承認とする）
- **P-002** 呼び出し元ゼロの dead code は grep 全数実測を根拠に退役してよい（実測結果を PR 本文に記載）
- **P-003** 「見送り」は正当な決着。根拠を Issue コメントに残して NOT_PLANNED close してよい
- **P-004** lint / 型の機械的追随は起票不要で同 PR に含めてよい（診断が指す範囲のみ。リファクタ同梱禁止）
- **P-005** ユーザー体験が変わる仕様分岐は実装で先行しない。decision キューに書いて次の Issue へ
- **P-006** 余白・文言などの UI ミクロ判断は既存パターン踏襲で実装者判断（迷いが残るなら PR 本文に 1 行明記）
- **P-007** 不可逆操作（データ削除・本番設定変更・履歴改変・force 系 git）はキュー不可。必ず同期でこうだいさんに確認
- **P-008** 実装中スコープ凍結: 実装中に計画外の追加・変更・削除が浮上したら、実装せずキュー（または outbox の Issue 起票依頼）へ積んで現計画を続行する。計画書の Scope / AC の変更・逸脱の自己免除は、こうだいさんの回答があるまで行わない（2026-08-10 承認・出典 = `docs/vision/plans/2026-08-10-harness-loop-consolidation.md`）

> 出自: P-002/P-003 は #429・#367 の裁定、P-004 は共通ゲート運用、P-005 は #428 の「判断に迷ったら停止」の一般化。
