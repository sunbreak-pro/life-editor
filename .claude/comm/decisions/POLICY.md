# 事前決裁ポリシー（POLICY）

「聞かなくていいこと」を増やすための恒久裁定集。判断に迷ったらまずここ → 該当なしなら、対話のチャットは最後の報告のあとに AskUserQuestion で聞き、無人の実行は decision キューへ書く（聞き方の元 = `rules/decision-queue.md`）。
**追加・変更はこうだいさんの明示承認のみ**（Claude が自分で裁定を足さない）。

- **P-001** merge と main への取り込みは、共通の決まり（claude-dotfiles の `claude/docs/development-flow.md` の「merge」）に従う。条件を満たした PR は、chat-main か、`issue-workflow` の仕上げ役 `work-finishers` が、共通の `merge-round` スキルで入れる。作業レーンは merge しない。定時実行と無人ループは merge しない。設定・hook・秘密の値・データベースの変更など、条件を満たしても確認を取る種類の PR は、共通の hook が止める。仕上げ役はその PR を飛ばし、chat-main が merge-round を回して、こうだいさんがその場で決める（2026-11-15 改定 = `decisions/2026-11-15-adopt-shared-merge-rules.md`。この改定を入れる PR の merge を明示承認とする）
- **P-002** 呼び出し元ゼロの dead code は grep 全数実測を根拠に退役してよい（実測結果を PR 本文に記載）
- **P-003** 「見送り」は正当な決着。根拠を Issue コメントに残して NOT_PLANNED close してよい
- **P-004** lint / 型の機械的追随は起票不要で同 PR に含めてよい（診断が指す範囲のみ。リファクタ同梱禁止）
- **P-005** ユーザー体験が変わる仕様分岐は実装で先行しない。対話のチャットは最後の報告のあとに聞き、無人の実行は decision キューに書いて次の Issue へ
- **P-006** 余白・文言などの UI ミクロ判断は既存パターン踏襲で実装者判断（迷いが残るなら PR 本文に 1 行明記）
- **P-007** 不可逆操作（データ削除・本番設定変更・履歴改変・force 系 git）はキュー不可。必ず同期でこうだいさんに確認
- **P-008** 実装中スコープ凍結: 実装中に計画外の追加・変更・削除が浮上したら、実装せずに現計画を続行する。対話のチャットは最後の報告のあとに聞き、無人の実行はキュー（または outbox の Issue 起票依頼）へ積む。計画書の Scope / AC の変更・逸脱の自己免除は、こうだいさんの回答があるまで行わない（2026-08-10 承認・出典 = `docs/vision/plans/2026-08-10-harness-loop-consolidation.md`）

> 出自: P-002/P-003 は #429・#367 の裁定、P-004 は共通ゲート運用、P-005 は #428 の「判断に迷ったら停止」の一般化。
