# Decision Queue — 判断の非同期キュー

ユーザー判断が要る点で作業を止めないための書き溜め場。outbox（連絡）と分離した「判断専用レーン」。

## ファイルと書込権限（単一書込者原則 — comm/README.md と同じ）

| ファイル | 書く人 | 読む人 |
| --- | --- | --- |
| `chat-<name>.md` | そのチャットのみ | 全員 |
| `ANSWERS.md` | こうだいさん（または転記を任された chat-main / digest セッション）のみ | 全員 |
| `POLICY.md` | こうだいさん承認の PR のみ | 全員 |

## エントリ形式（依頼側）

### YYYY-MM-DD-<中身を表す英語の短い名前>: <問いを 1 行>

（見出しの名前は、回答後に作る決定の記録のファイル名になる。日付は起票日、英語の名前は小文字・数字・`-` だけで書く。キューと `decisions/` に同じ名前が無いことを確かめてから書く。2026-11-15 より前の `D-YYYYMMDD-<chat略称>-<連番>` の見出しは、そのまま読める）

- 背景: <Issue 番号 / file:line / 1 行で>
- A: <選択肢>（推奨 — 理由 1 行）
- B: <選択肢>
- 放置時: <安全側の挙動。「この Issue を保留して次へ」等。無回答で作業が勝手に進む選択肢を置かない>
- 期限感: <merge 前まで / 今週末 / いつでも>

## 回答形式（ANSWERS.md・1 行/件）

- 2026-11-15-adopt-shared-merge-rules: A（一言あれば続ける）

過去の行（`- D-20260728-sched-1: A`）は書き直さない。`records.mjs` は両方の形の行を読んで、決定の記録と突き合わせる。

## 運用

- 依頼側はエントリを書いたら**その判断をブロックせず次の作業単位へ進む**
- セッション開始時に ANSWERS.md を確認。自分宛の回答があれば、**まず `.claude/decisions/<見出しの名前>.md` へ昇格**（キュー本文をそのまま貼って恒久保存 — 手順 = `.claude/decisions/README.md`）してから、エントリを自分のファイルから削除して着手（ANSWERS.md 側の行は消さない — 監査ログを兼ねる）
- 月次で `comm/archive/YYYY-MM/` へ退避（outbox と同じローリング）
- ここに書いてよいのは「A/B に割れる判断」だけ。**不可逆操作（データ削除・本番設定変更・履歴改変）はキュー不可** — POLICY.md の方針「不可逆操作は同期で確認する」に従い同期でユーザー確認
