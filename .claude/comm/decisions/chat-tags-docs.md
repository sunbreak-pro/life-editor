## D-20260812-tags-1: タグ編集パネルの保存ボタンを「pending がある行にだけ出す」か「全行に常設して disabled で出す」か

**背景**: #715（PR #727・merge 済み）でタグ編集パネルの改名を保存ボタン方式にした。その際、保存ボタンを**書きかけのある行にだけ出す**実装にしている（`shared/src/components/TagEditModal.tsx`・テストの pin = `shared/tests/tagEditModalSave.test.tsx` の「offers no save button while the name matches the stored one」）。見た目が変わる仕様分岐なので P-005 に従いキューへ。**実装は merge 済みのため、この判断はコードを変えずに記録だけ残す**（B を選ぶ場合は別 Issue で直す）。

**A（採用・現行実装）: pending のある行にだけ出す**（推奨）

- 利点: タグ一覧は N 行あるので、常設にすると**押せないボタンが行数ぶん縦に並ぶ**。押せるボタンが 1 つだけ現れるほうが「今どの行が書きかけか」も同時に伝わる
- 欠点: ボタンが出たり消えたりして行の幅が動く。1 アイテムの詳細パネル（#681）と流儀が揃わない

**B: #681 と同じく常設 disabled に揃える**

- 利点: 「保存はボタンで確定する」という同じ約束を、アプリ全体で同じ見え方にできる。ボタンの出現でレイアウトが動かない
- 欠点: #681 は**1 アイテムの詳細パネル**、こちらは**N 行のリスト**という違いがある。同じ流儀をそのまま持ち込むと、押せないボタンが列を作る

**#434 S-1（書けないものは押せない形にしない）はどちらでも満たす**: A は「押せないボタンを出さない」、B は「押せないことを disabled で明示する」で、どちらも「押したのに何も起きない」を作らない。

**放置時**: **A のまま**（実装済みなので実害なし）。B に倒す場合のみ別 Issue を立てて直す。

**期限感**: いつでも（現行動作で困りが出たときに再検討で可）
