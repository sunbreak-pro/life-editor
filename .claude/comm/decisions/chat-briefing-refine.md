### D-20260818-briefing-1: 夕刊のフォーカス入力欄の見出しを「明日のフォーカス」にした（#1048 の文言判断）

- 背景: #1048 の DoD は「夕刊に『今日のフォーカス』の入力欄」だが、夕刊で書いた内容は**翌朝**の朝刊が「今日のフォーカス」として表示する。夕刊の時点では明日の話なので、入力欄の見出しを Issue の字面どおり「今日のフォーカス」にすると「今日＝もう終わる日」と読めて逆向きになる
- A: **実装のまま = 夕刊側は「明日のフォーカス」（en: TOMORROW'S FOCUS）、朝刊側は従来どおり「今日のフォーカス」**（推奨 — 書く晩と読む朝で指す日が同じになる）
- B: Issue の字面どおり夕刊側も「今日のフォーカス」にする（名前は揃うが、指す日が晩と朝でずれる）
- 放置時: A（PR は A で実装済み。B に倒すなら i18n 2 キーの文言変更のみ）
- 期限感: いつでも（実害なし・文言だけ）

### D-20260816-briefing-1: 週開始曜日を切り替えたとき、今週の目標をどう扱うか

- 背景: #957（PR #973）で目標を期間キー付きにした。週のキーは**その週の開始日**（`startOfWeekKey(todayKey, weekStartsOn)`）なので、`useWeekStartPref` を日曜始まり ⇄ 月曜始まりで切り替えるとキーが 1 日ずれ、**書いたばかりの今週の目標が履歴側へ回って欄が空になる**（本文には残るので消失ではなく「見えなくなる」）。実測: 現状 `useWeekStartPref` に Settings の書き込み UI は無く、手で localStorage を触ったときだけ起きる
- A: **現状維持 = キー完全一致のみ**（推奨 — ルールが 1 つで済み、「見出しのキー = 現在の期間」以外の判定を持ち込まない。週の定義を変えたのだから別のバケツになる、という説明も筋が通る）
- B: 現在の週キーに一致するセクションが無いとき、**キーが今週の範囲 [週初, 週末] に入っている週セクションを拾って採用する**（切替に追従して見え続ける。ただし「一致」と「範囲」の 2 種類の判定が並び、範囲内に 2 つあったときどちらを採るかという規則が要る）
- 放置時: A（PR #973 は A で実装済み。B に倒すなら追い実装の別 Issue）
- 期限感: いつでも（Settings に週開始曜日の切替 UI を足すときまでには決める）
