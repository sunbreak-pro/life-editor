# 採点表 — 見た目の 5 観点

> 採点者は、その画面の案を作った人でも実装した人でもないエージェントにする。点は 1〜5 の整数で付け、各点に「根拠になった数値」と「スクリーンショットのどこを見たか」を必ず添える。根拠の無い点は無効にする。

## 点の付け方の共通ルール

- 5 = 直す所が見つからない / 4 = 小さな直しが 1〜2 個 / 3 = 直すべき所が 3 個以上、または目立つものが 1 個 / 2 = 画面の印象を損ねている / 1 = 使うのに支障がある。
- Desktop（1280×800）と Mobile（390×844）は別々に採点する。ライトとダークで差があるときは、低いほうの点を採る。
- 数値は `scripts/measure.js` の返り値から引用する。目視の所見は、`visual-inspect` スキルで切り抜いて拡大した画像を根拠にする。
- 良くするための提案は、点とは別の欄に書く。提案を書いたことを理由に点を上げ下げしない。

## 1. アイコン

見ること: その画面に要らないアイコンが無いか、意味の分かりにくいアイコンが無いか、大きさが揃っているか。

| 数値（measure.js）                 | 目安                                                               |
| ---------------------------------- | ------------------------------------------------------------------ |
| `counts.iconSizeKinds`             | 1 画面で 3 種類以下。多いほど揃っていない。                        |
| `counts.unlabeledIconOnlyControls` | 0 にする。1 つでもあれば 3 点以下。                                |
| `icons.byName`                     | 同じアイコンが別の意味で使われていないかを目で確かめる材料にする。 |

目で見て判断すること:

- **要らないアイコン**: 隣の文字と同じことを言っているだけのアイコン、押せないのに押せそうに見えるアイコンを挙げる。
- **分かりにくいアイコン**: 文字のラベルを隠したときに、何をするボタンか当てられないものを挙げる。
- **意味の重なり**: 同じ画面の中で、同じ操作に別のアイコンが使われていないか、別の操作に同じアイコンが使われていないかを見る。

## 2. 余白

見ること: まとまりの中は詰め、まとまりの間は空ける、というリズムが守られているか。

| 数値（measure.js）         | 目安                                                       |
| -------------------------- | ---------------------------------------------------------- |
| `counts.spacingOffScale`   | 段階から外れた値の数。0 が理想で、10 を超えたら 3 点以下。 |
| `counts.spacingValueKinds` | 使われている余白の値の種類。少ないほど揃っている。         |

目で見て判断すること:

- 見出しと中身の距離が、中身同士の距離より近くなっていないか（近い = 同じまとまりに見える）。
- 詰まりすぎて押し間違えそうな場所、空きすぎて別の画面に見える場所が無いか。
- カードやリストの行の内側の余白が、同じ種類の部品同士で揃っているか。

## 3. アニメーション

見ること: 動きが意味を持っているか。動きが多すぎたり遅すぎたりしないか。

| 数値（measure.js）           | 目安                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `counts.motionOffBand`       | `frontend-react-designer` の `references/motion.md` §3 の 3 帯から外れた数。0 が理想。 |
| `counts.motionDurationKinds` | 長さの種類。帯ごとに 1 種類ずつ、計 3 種類程度に収まっているか。                       |

目で見て判断すること（実際に操作して確かめる）:

- 開く・閉じる・完了する、のように「その瞬間」を伝える動きになっているか。飾りだけの動きが無いか。
- 同じ種類の操作（パネルの開閉など）が、画面ごとに違う動き方をしていないか。
- OS の「視差効果を減らす」を有効にしたとき、動きが止まるか（`browser_emulate_media` で `reducedMotion: "reduce"`）。

## 4. 視覚の階層

見ること: 画面を開いて最初に目が行く場所が、その画面で一番大事な情報になっているか。

| 数値（measure.js）     | 目安                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| `counts.fontSizeKinds` | 文字の大きさの種類。5 種類を超えると、どれが大事か読み取りにくくなる。 |

目で見て判断すること:

- スクリーンショットを縮小して（幅 320px 程度）ぼかして見たとき、一番目立つ塊が何かを書き出す。それがその画面の役割と合っているかを見る。
- 強調（太字・色・大きさ）が 1 画面に何か所あるかを数える。強調が多すぎると、どれも目立たなくなる。

## 5. 画面をまたいだ揃い方

見ること: その画面が、ほかの画面と同じアプリに見えるか。

- 同じ部品（ヘッダー、ボタン、カード、右サイドバー）の寸法・余白・角丸が、ほかの画面と揃っているかを比べる。比較の相手は Schedule と Materials にする（利用頻度が高く、見直しが進んでいるため）。
- 色は `lumen-*` のトークンだけを使っているか。直書きの色は `frontend-react-designer` の仕上げチェックの grep で確かめる。

## 出力の形

採点者は次の表を返す。点の合計は出さない（観点ごとに重みが違い、合計すると弱点が隠れるため）。

```markdown
| 観点     | Desktop | Mobile | 根拠（数値）                 | 根拠（どこを見たか）         |
| -------- | ------- | ------ | ---------------------------- | ---------------------------- |
| アイコン | 3       | 2      | iconSizeKinds=5, unlabeled=1 | 右上の「…」と「⚙」が同じ操作 |
```

表のあとに、直す候補を「要らないアイコン / 分かりにくいアイコン / 余白 / 動き / 階層 / 揃い方」の見出しで並べる。各候補には、場所（コンポーネントのファイル名か画面上の位置）を書く。
