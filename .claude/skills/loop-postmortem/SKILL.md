# /loop-postmortem — 失敗から 1 行を回収する

## 目標

直近の失敗・手戻り・停止したループを読み、**再発を防ぐ 1 行**をどこに足すか決めて足す。足さない判断も成果に数える。

## 完了条件（機械検証可能）

- 対象にした失敗ごとに「足した 1 行 + 足した先のファイル」か「足さない理由 1 行」のどちらかがついている
- 足した行がすべて既存文書の**既存の節の中**にある（新規ファイル・新規章を作っていない）
- 同じ内容が既に別の文書にある場合、二重に書かず参照にしてある（数値の非複製原則）

## 予算

- 反復上限: **5 件**（1 反復 = 1 つの失敗）。多い週でも 5 件で切る。残りは次回に回す
- 時間上限: **20 分**。開始直後に `START_TS=$(date +%s)` を取る
- **1 件につき足すのは 1 行**。3 行書きたくなったら、それは 1 行にまとまっていない証拠なので削る

## 停止条件（人間に返す）

- **足す先が判断できない**（Issue なのか `docs/known-issues/` なのか `rules/` なのか CLAUDE.md なのかが割れる）
- 再発防止に**規約の変更**が要ると分かった（1 行足すのではなく、既存のルールを書き換える話）
- 同じ失敗が 3 回以上出てきた（文書を足す問題ではない。機械強制か設計の見直しが要る）
- 足す先が他チャットの持ち物（単一書込者原則。自分の outbox に依頼を append する）

## 使ってよい道具

- `docs-workflow` スキル — Issue と `docs/known-issues/` の境界・起票の一元化・plans のライフサイクルの正本
- `task-tracker` スキル — per-chat の `memory/` と `history/` の記録
- 収集源: `.claude/comm/outbox/`・`.claude/comm/decisions/`・停止したループの仮説・`gh issue list --state closed --search`

## 環境の事実（推論では埋まらないので明記する）

- **足す先の判定は「life-editor のコードを直せば直るか？」**。Yes なら Issue、No（Claude Code の環境 / hook / ツール挙動）なら `docs/known-issues/` + `rules/`。Issue はプロダクト課題専用
- **起票は chat-main 一元**。worktree チャットは自分で起票せず outbox に依頼を append する
- 数値・個数・列挙は正本 1 か所だけに書く。他の文書には参照を書く（改名・退役時に必ず漏れるため — `rules/docs-consistency.md`）
- 歴史的記述として残す行には「旧称」「retired」等の注記を同じ行に付ける（docs-lint の除外条件）

---

- **足さない判断を恐れない**。文書は増えるほど読まれなくなる。「その行を消したら Claude が間違うか」で決める
- 増えたぶんを畳む `loop-prune` は姉妹計画（`2026-08-04-context-cost-reduction-harness.md`）の担当。それが来るまで、足す量は自分で抑える
- 実測した件数・所要時間は、区切りで `2026-08-04-loop-catalog-implementation.md` の Worklog に 1 行足す
