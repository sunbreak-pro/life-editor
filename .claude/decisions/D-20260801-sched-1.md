# D-20260801-sched-1: パレットから予定へ移動したとき、掛かっているカレンダーレンズをどうするか（#520）

## 背景

#503（パレットのアイテム横断検索）と #468（台帳のタグレンズ）は単体では正しく、噛み合ったときだけ壊れる。レンズを掛けた状態でパレットから対象外の予定を選ぶと、`anchorDate` と `selectedId` は書かれるのに `applyCalendarLens` がその行をグリッドから落とすので、**日付だけ飛んで何も起きなかったように見える**。Issue #520 が 🛑 として「実装前に決める」と明記している（#506 の cancel 側を合流させなかった前例があるため自明ではない）。

## 選択肢と裁定

- A: **移動時にレンズを外す**（**採用** — ユーザー回答 2026-08-01。生成 4 経路の `finishCreatePanel()` と同じ扱いにする → #520 の 🛑 ゲート解除・実装可）
  - 利点: 選んだ予定が必ず見える。既存の合流点に 1 行足すだけで、次に増える移動経路も同じ穴を開けにくい
  - 欠点: ユーザーが意図して掛けた絞り込みが黙って消える（#506 で cancel 側を合流させなかった理由と同じ懸念）
- B: レンズは維持し「対象外だから出ていない」と伝える — バナー / トースト / 空状態の文言のいずれかで理由を出す（却下）
  - 利点: 絞り込みの意図を尊重する。レンズは「今どれを見るか」の宣言なので、移動で勝手に解けない方が筋は通る
  - 欠点: 伝える UI の設計が要る（置き場所・文言・消え方）。差分が A より確実に大きい
