# D-20261028-main-1: 画面が変わる計画は、実装前にデザインシステムと Artifact で UI / UX を確かめてから書くか

## 背景

キューを経ず、chat-main の会話でこうだいさんが直接指示した（2026-10-28）。原文は次のとおり。

> 新しい機能やデザインを作成する際には、今後実装に入る前に以下のデザインシステムと Artifacts を用いて UI,UX を確認しながら計画書を作成してほしい。その設定をルール化してほしい

指定されたのは、Artifact の「Life Editor」デザインシステム（https://claude.ai/artifact/KPdEWuLhoeL9MdzRRa43Aa）と、Claude Design の試作プロジェクト `Life Editor.dc.html`（https://claude.ai/design/p/90a82a78-0ef6-419a-80dd-0739acaa9df9?file=Life+Editor.dc.html&via=share）の 2 つ。同じ会話で、Materials のメイン部分の UI / UX を一新したいという希望も出ており、その計画がこの手順の最初の対象になる（#2373）。

## 選択肢と裁定

- A: 画面が変わる新機能・改修は、デザインシステムを使って Artifact で案を作り、こうだいさんの確認を経てから計画書を確定し、実装に入る（**採用** — こうだいさんの指示 2026-10-28。文字だけの計画書では、画面の食い違いが実装のあとで分かり作り直しになるため）
- B: 従来どおり、計画書は文字で書き、画面の確認は実装後の実ブラウザ確認に任せる（却下 — 上の理由）

## 波及

- `.claude/rules/design-first-planning.md` を新設（対象・使うもの・手順・Gate）。
- `.claude/docs/vision/plans/_TEMPLATE.md` に「UI / UX の確認」節を追加。
