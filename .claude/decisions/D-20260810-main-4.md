# D-20260810-main-4: #607 の修正を「触らない」宣言済みの `useNotesUnifiedAPI.ts` に入れるか

## 背景

`2026-08-10-mobile-keyboard-input-fixes.md` は Scope の「触らない」に `shared/src/hooks/useNotesUnifiedAPI.ts` を挙げていた（#587 = shared-fix レーンがこのファイルの分割を予定しているため）。ところが Step 0 の実測で #607（スマホで Note に書き込めない）の原因が**まさにそのファイル**にあると確定した — 自分の書き込みが載せるクライアント時計の `updatedAt` が、リロード時のマージ判定（`prev.updatedAt === row.updatedAt`）を必ず外し、いま編集中のノートだけが hydrate 済みセットから落ちる。

P-008（実装中スコープ凍結・Scope 逸脱の自己免除禁止）に該当するため、実装を止めて裁定を仰いだ。

実測した衝突リスク: **#587 は未着手**（open PR ゼロ・`shared-fix` worktree は #372 を作業中）。今回の差分は同ファイルに約 15 行の追加。

## 選択肢と裁定

- A: **同じ PR に含め、計画書の Scope に例外として追記**（**採用** — ユーザー回答 2026-08-10）。壊れている主導線（スマホから Note が書けない）が今日塞がる。#587 の分割時に付け替えが要るが、15 行の追加なので移送は容易
- B: #608 だけ先に出し、#607 は shared-fix レーンへ回す（却下 — Scope 宣言は守れるが、#587 の着手時期が未定のまま「書けない」が続く）
- C: #587 の分割を先に片付けてから #607 を分割後のファイルに載せる（却下 — 衝突はゼロになるが、バグ修正が構造改善の完了待ちになる）
