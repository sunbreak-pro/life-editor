# D-20261007-main-6: 重複防止のキーの決まり（同じキーで中身が違うとき、ソフトデリート済みのキーのとき）

## 背景（キュー原文）

- 背景: 計画書 R5。重複防止のキーがあると、拡張アプリは「少なくとも 1 回送る」だけで結果を 1 件にそろえられる。
- A: 中身が違えば専用の code で断る。ソフトデリート済みの項目は新しく作らず、「削除済み」の code を返す（推奨 — こうだいさんが消した項目を、拡張アプリが無言で作り直すことを防げる）
- B: 中身が違っても最初の結果を返す。ソフトデリート済みなら新しく作り直す（拡張アプリの実装は単純になるが、消した項目が戻る）
- 放置時: 冪等の AC を確定せず、Step 6 に着手しない
- 期限感: 窓口の着手前まで

## 裁定
