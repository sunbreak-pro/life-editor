# D-20260816-shared-fix-5: 再設定を完了せず離脱したとき、セッションを切るか残すか

## 背景

（キューのエントリ本文をそのまま貼る）

- 背景: リカバリーリンクは**踏んだ時点でサインインさせる**。#919 では「まだ新パスワードを設定していない」印を sessionStorage に置いたので、リロードや戻るでは再設定カードに留まる。ただしタブを閉じると印だけが消え、次にそのブラウザで開くと**古いパスワードのまま普通に入れる**
- A: 現状維持（推奨 — 「リンクを踏んだらとりあえず中に入れる」ほうが実用的。パスワードを忘れていること自体は既知で、後からいつでも Settings で変えられる）
- B: 再設定カードに「やめる」を置き、離脱時は `signOut()` する（未再設定のセッションを端末に残さない。厳密には安全側だが、閉じ忘れただけで締め出される）
- 放置時: A の現状維持
- 期限感: いつでも

## 選択肢と裁定

- **A: 現状維持（セッションを残す）**（**採用** — ユーザー回答 2026-08-16）。「リンクを踏んだらとりあえず中に入れる」ほうが実用的で、パスワードを忘れていること自体は本人にとって既知。後から Settings のアカウントカードでいつでも変えられる
- B: 再設定カードに「やめる」を置き離脱時 `signOut()`（却下 — 未再設定のセッションを端末に残さない点は厳密に安全側だが、タブを閉じ忘れただけで締め出される。N=1 で端末が本人専用という前提では手間が損得を上回る）

## 却下案が復活する条件

- 共用端末から公開 Web URL を開く運用に変わったとき（D-20260816-shared-fix-3 の復活条件と同根）

## 波及

- #919 で入れた sessionStorage の「未再設定」印はそのまま維持（リロード・戻るで再設定カードに留まる挙動は A の一部）
