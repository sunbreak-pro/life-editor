# D-20260812-tags-1: タグ編集パネルの保存ボタンを「pending がある行にだけ出す」か「全行に常設して disabled で出す」か

## 背景

（キュー原文 = `comm/decisions/chat-tags-docs.md`）

#715（PR #727・merge 済み）でタグ編集パネルの改名を保存ボタン方式にした。その際、保存ボタンを**書きかけのある行にだけ出す**実装にしている（`shared/src/components/TagEditModal.tsx`・テストの pin = `shared/tests/tagEditModalSave.test.tsx` の「offers no save button while the name matches the stored one」）。見た目が変わる仕様分岐なので P-005 に従いキューへ。**実装は merge 済みのため、この判断はコードを変えずに記録だけ残す**（B を選ぶ場合は別 Issue で直す）。

**#434 S-1（書けないものは押せない形にしない）はどちらでも満たす**: A は「押せないボタンを出さない」、B は「押せないことを disabled で明示する」で、どちらも「押したのに何も起きない」を作らない。

## 選択肢と裁定

キューの A / B は**どちらも採られなかった**。ユーザーの回答は「もう少し別の UI/UX を考案してほしい。パネル内のカラムを二つにするのもありだと思うがどうか」で、これを受けて出し直した 4 案から **2 カラム（マスター・ディテール）案**が選ばれた。

- **採用: 2 カラム（左 = タグ一覧 / 右 = 選択中タグの編集）**（ユーザー回答 2026-08-12）。左は色ドット + タグ名 + 件数だけで幅が動かない。右に名前 / 色 / アイコン / 付いているアイテム一覧を置き、**保存ボタンは右下に 1 つだけ常設**（#681 の詳細パネルと同じ流儀 = D-20260810-sched-1）、削除はその左。未保存のまま別のタグを選んだら in-app 確認（#729 の流儀・`window.confirm` は使わない）。狭幅は縦 2 段に畳んで戻る導線をつける
  - 採った理由: A / B の争点だった「押せないボタンが行数ぶん並ぶ」も「ボタンの出入りで行がずれる」も、編集面を 1 つに絞ることで両方消える。1 行に 6 要素が詰まっている今の窮屈さも同時に解ける
- A（キュー原案）: pending のある行にだけ保存ボタンを出す = 現行実装（却下 — 押せるボタンが 1 つだけ現れる利点はあるが、ボタンの出入りで行の幅が動き、#681 の詳細パネルと流儀が揃わない）
- B（キュー原案）: #681 と同じく全行に常設 disabled（却下 — レイアウトは動かなくなるが、#681 は 1 アイテムの詳細パネル、こちらは N 行のリスト。押せないボタンが列を作る）
