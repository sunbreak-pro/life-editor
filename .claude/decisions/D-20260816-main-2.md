# D-20260816-main-2: CLAUDE.md §7.1 のコマンド表を CI に追随させるか、列挙自体をやめるか

## 背景

§7.1 は「PR 前は上のブロックの lint / build / test をすべて回す」と書いていたが、表に `typecheck:tests`（shared / web）と mcp-server の build / test が載っていなかった。どちらも `.github/workflows/ci.yml` にある独立ゲートで、`npm run build` はテストファイルを見ず、`vitest` は型を見ないため、**ローカル全緑 → CI だけ赤**が起きる。

実測で 4 回刺さった:

- PR #924（#892）— `TodoNodeType` が単値なのにテストが `type: "folder"` を渡していた
- PR #980（#955）— `DailyNode` に無い `type` をテスト fixture が渡していた
- PR #842 — `mock.calls[0][2]` が空タプル型で TS2493
- PR #985 — `vi.spyOn(console,"warn")` の `mock.calls` を map する引数が implicit any（TS7006）

ほかに #821 / #822 の mcp-server 衝突が main で初めて赤くなった件（修理 = PR #829）も同型。

- A: 表に 4 行足す（`cd shared && npm run typecheck:tests` / `cd web && npm run typecheck:tests` / `cd mcp-server && npm run build` / `cd mcp-server && npm run test`）
- B: コマンド列挙をやめ、`.github/workflows/ci.yml` を正本と明記して §7.1 は参照だけにする
- 放置時: A も B も入らず、同じ漏れ方が続く
- 期限感: 早い（1 日に 2〜4 本の PR が同じ穴に落ちている）

## 選択肢と裁定

- A: 表に 4 行足す（却下 — 表は「手で写した複製」であり、CI にゲートが増えるたびに再び遅れる。2026-08-13 と 2026-08-16 に同じ依頼が 2 度出ている時点で、追随の運用が機能していないことが実証されている）
- **B: 列挙をやめて `ci.yml` を正本と明記する**（**採用** — ユーザー回答 2026-08-16）。§7.1 は既に「ゲート一覧の正本は ci.yml」と書いており、複製をやめれば数値の非複製原則（CLAUDE.md §0）と一致する。読み手は `verify` ジョブのステップ列を上から `working-directory` ごとに打てばよく、ゲートが増えても文書の更新が要らない

## 却下案が復活する条件

- `ci.yml` が読んで分からない形（matrix / 再利用ワークフロー / composite action への抽象化）に育った場合。そのときは「ステップ列を上から読む」が成立しなくなるので、人間向けの写しが再び要る

## 波及

- 実装 Issue = **#1010**。§7.1 からコマンドブロックを削除し、`ci.yml` への参照 + 回し方 + 「コマンド名からは読み取れない罠」4 点（build はテストを見ない / web の lint は web/ しか歩かない / TypeScript の版が web だけ違う / docs-lint は `LC_ALL=C`）だけを残す
- ローカル起動（`cd web && npm run dev`）は CI に無いので §7.1 に残す
- `web/tests/` に jsdom のレイアウトが無い件（#475）は §7.1 の別段落として据え置き
