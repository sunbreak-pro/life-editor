# D-20260810-main-1: プロジェクト固有スキル / エージェントの実体をどこに置くか

## 背景

`.claude/skills/` の 8 本と `.claude/agents/` の 2 本が、リポジトリ外の共有ライブラリ（`~/dev/Claude/skill-lib` / `agents-lib`）を指す **Mac 絶対パスの symlink**（git mode `120000`）としてコミットされていた（known-issues 031）。共有ライブラリ側は git リポジトリですらなく、Windows 実機へ配る経路が存在しない。Windows セッションではこれらが一覧に載らず、名指しで委譲する指示が**エラーも出さずに空振り**していた。

hooks は同じ構造を fallback chain（`$HOME/dev/Claude/hooks-lib` → 無ければ `.claude/scripts/hooks-lib/`）で解決済みだが、**スキル / エージェントには同じ手が使えない**。Claude Code はスキルをディレクトリ一覧で発見するため、間に振り分けスクリプトを挟む余地が無い。

## 選択肢と裁定

- A: **repo 内 vendor 化・共有ライブラリ側は削除**（**採用** — ユーザー回答 2026-08-10）。10 本を実ファイルとしてリポジトリに取り込み、life-editor repo を唯一の正本にする。`skill-lib` / `agents-lib` の `projects/life-editor/` は削除して二重管理を断つ（他プロジェクト = novel 等の分は無傷で残す）
- B: repo に実体化しつつ共有ライブラリ側も残す（却下 — どちらを直したか分からなくなる二重管理。改名 sweep で片側だけ更新される事故が実際に起きている = ink→lumen 3 世代併存）
- C: `skill-lib` 自体を git 化して submodule 参照（却下 — 複数プロジェクトで共有し続けられる利点はあるが、submodule は Windows での運用コストが高く、N=1 のプロジェクトに対して仕組みが重い）

## 波及

- `.claude/skills/`（8 本）・`.claude/agents/`（2 本）を mode `120000` → `100644` に置換
- `Skill.md` → `SKILL.md` 正規化 5 本（case-sensitive な FS で読めない潜在バグの解消）
- CLAUDE.md §4 / §7.0 の「Mac のみ実体」注記を削除し、§7.0 に「repo 外を指す symlink を作らない」不変式を追加
- `rules/docs-consistency.md` §2 の sweep 対象から repo 外 grep を削除
- `skills/loop-implement` / `loop-triage` / `loop-postmortem` の環境注記を更新
- known-issues 031 を Fixed 化
- **共有ライブラリ側の削除は PR merge 後**に実施する（merge 前に消すと、まだ symlink を持つ他 worktree の参照が全部切れるため）
