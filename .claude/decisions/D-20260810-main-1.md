# D-20260810-main-1: END の task-tracker をいつ実行するか（verifier 直後 / 実装 PR の merge 後）

## 背景

（本件はキューを経ずチャットで直接裁定されたため、背景はセッションの経緯から再構成した — キュー原文は存在しない）

2026-08-01 の [`D-20260801-main-1`](./D-20260801-main-1.md) で「tracker（`memory/` + `history/`）の更新を実装ブランチに載せない」が確定し、その反映として CLAUDE.md §7.4 と `skills/worktree-policy/SKILL.md` に「**merge 後に 1 commit でまとめる**」と書かれた。載せ場所の裁定としては正しいが、**実行タイミングまで merge 後に縛った**結果、END の tracker が実装 PR の merge 待ちになる。

merge は P-001 で常にこうだいさんの手番なので、セッションは「merge したら声をかけてください」で停止する。こうだいさんが戻って merge → 声かけ → Claude が tracker、という往復が挟まり、計画 → 実装 → 検証 → 改善のループが人待ちで止まる。同日の [#618](https://github.com/sunbreak-pro/life-editor/issues/618)（破壊的操作以外の確認ゲート撤去）と同じ「確認待ちの摩擦を取る」文脈で、2026-08-10 にこうだいさんが裁定した。

## 選択肢と裁定

- A: **verifier 緑の直後に tracker を実行する**（**採用** — ユーザー回答 2026-08-10）。`session-verifier` が緑になったら、ユーザーの確認も実装 PR の merge も待たずにそのまま END の tracker（`memory/` + `history/` 更新・plan の COMPLETED 化 + archive 移動）まで進める。tracker 専用ブランチ `chore/tracker-main-YYYYMMDD` を切って即 commit → PR まで出す。実装 PR の状態は**書いた時点の実測**（open / merged）で記す — 「merge 済み」の記録が欲しいなら後追いでなく、その時点の事実を書けば足りる
- B: 現状維持（却下 — 記録は常に merge 後の確定状態になるが、その代償として全セッションの終端が人待ちになる。merge が翌日にずれると tracker も翌日にずれ、セッションの記憶が薄れてから書くことになって記録の質も落ちる）

**`D-20260801-main-1` は維持**する。本裁定が置き換えるのは「いつ実行するか」だけで、「tracker を実装ブランチに載せない」（= 専用ブランチに分ける）原則はそのまま残る。並行ブランチの衝突はブランチ分離で防げており、タイミングを merge 後に縛る必要はない。

## 波及

- CLAUDE.md §7.4 / `skills/worktree-policy/SKILL.md`（「merge 後に 1 commit でまとめる」→ verifier 直後・専用ブランチで即 commit → PR）
- `claude-dotfiles`: `skills/task-tracker/SKILL.md`（END フローの実行タイミング）・`skills/lead-pipeline/SKILL.md`（中ティア連鎖 verifier → tracker）
