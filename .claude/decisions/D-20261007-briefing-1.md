# D-20261007-briefing-1: 朝刊や宣言の節の後ろに書いた文章が 1 本の文章から外れる件を、どう直しますか

## 背景

（キューを経ず、PR #2139 の本文の「こうだいさんの判断が要ること」に、こうだいさんがチャットで直接答えた。キュー原文が無いため、PR の本文と回答から再構成した）

- 計画書は、Daily の本文の節を「見出しから次の見出しまで」と決めています。1 本の文章（D-20261006-main-5）は、本文から朝刊の節・宣言の節・夕刊の見出し・気分の行を除いた残りです。
- そのため、見出しの無い文章が朝刊や宣言の行の後ろにあると、その文章は朝刊や宣言の節の一部になり、1 本の文章から外れます。夕刊の締めくくりの欄にも、#2123 の Daily の本文にも出ません。
- そうなる経路は 2 つありました。1 つ目は、MCP の `write_briefing` が今までの本文の前に朝刊の節を入れることです。2 つ目は、宣言を書いたあとに Daily の末尾へ書いた文章が、宣言の節に入ることです。
- 宣言を保存する処理（`mergeIntentionSection`）は宣言の節を丸ごと置き換えるので、あとで宣言を保存すると、その文章は消えます。

## 選択肢と裁定

- A: 今の決まり（節は次の見出しまで）のまま残し、既知の限界として扱う（却下 — 朝刊を書いた日に、今までの本文がまるごと見えなくなるため）。
- B: 朝刊と宣言の節を、書き手が書いた行だけに狭める（却下 — 古い日の本文では、どこまでが書き手の行かを確かめる手がかりが無いため）。
- C: 朝刊や宣言の内容を Daily の本文に書かない。Daily の中の別の欄に記録する（**採用** — ユーザー回答 2026-10-07「朝刊や宣言の内容を Daily には記述しないようにする。Daily の中の別の UI, UX に記録されるようにする」）。

## 波及

- **朝刊の講評の保存先**: `dailies_payload` に `morning_comment`（jsonb の配列）を足します（`supabase/migrations/0035_dailies_morning_comment.sql`）。MCP の `write_briefing` は講評をこの列に書き、本文には書きません。フォーカスの 1 行は今までどおり予約ノート `note-focus` です。
- **宣言**: #2106 と #2107 で、アプリから宣言を書く経路が無くなります。MCP にも宣言の書き手はありません。そのため列は作りません。
- **古い日**: 本文の朝刊・宣言の節は書き換えずに残します。読むときは列を先に見て、列が無い日だけ本文の朝刊の節を読みます。
- **読む関数**: `shared/src/components/briefing/dailyMorning.ts` の `readMorningRecord` が、講評と宣言の文章を返します。古い日の節の中にある見出しの無い文章も、この関数が返す側に入ります。#2123 の Daily はこれを使って、講評と宣言を本文とは別の欄に出します。こうすると、節に入っていた文章も Daily の画面で見えます。
- **merge の順番**: アプリと MCP は `morning_comment` を名前で select するので、こうだいさんの `supabase db push` が先で、merge と Worker の deploy が後です。
- D-20261006-main-6（朝刊の節も Daily の本文の画面から外す）は変えません。この裁定は、それを保存先の側まで進めたものです。
- 実装は PR #2139（#2107 の夕刊の作り直し）に足しました。
