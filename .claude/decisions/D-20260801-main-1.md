# D-20260801-main-1: 1 レーンが多ブランチを並行させたときの tracker ファイル衝突をどうするか

## 背景

2026-08-01、schedule-refine が 5 本のブランチを並行で持った状態で #506 が merge された瞬間、**残り 4 本すべてが `.claude/history/chat-schedule-refine.md` で衝突**した（#516 は `memory/` も）。`git merge-tree` で実測したところ**コードは全部 auto-merge 可能**で、衝突は tracker ファイルだけ。1 本 merge するたびに次が再衝突するので、4 本ぶんの手作業が要る。

## 選択肢と裁定

- A: tracker の更新を**作業ブランチに載せない**（**採用** — ユーザー回答 2026-08-01。実装 PR では触らず、merge 後に 1 commit でまとめる）。衝突は構造的に消えるが、PR 単位で「何をしたか」の記録が同時に残らなくなる — 補いとして PR 本文側に要約を書く
- B: tracker を追記のみ・1 行 1 エントリに制限する（却下 — git の 3-way は同じ行に触らなければ通るが、今は複数行ブロックを同じ位置に足すので必ず当たる。書式の全面変更が要る）
- C: 現状維持・衝突するたびに手で解消（却下 — レーンが 3 本以上のブランチを並行させるたびに再発する）
