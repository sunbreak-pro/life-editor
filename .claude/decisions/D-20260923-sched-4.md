# D-20260923-sched-4: 予定を複製したとき、タグを引き継ぐか（K-06）

## 背景

（キューを経ていない。問いの原文は計画書 `2026-09-23-schedule-refactor-phase2.md` §承認時に決めてほしいこと の Q4 で、PR #1955 の本文にも同じ表がある。2026-09-26 に chat-main が AskUserQuestion で代行して質問・昇格した）

- 複製（`web/src/schedule/useScheduleMutations.ts` の `handleDuplicate`）は、元の予定のタグを新しい予定に付けない。
- 推奨は「引き継がない（現状維持）」だった。タグの書き込みは第 2 期の Scope 外の `useWikiTagsUnifiedAPI` にあり、引き継ぐと「1 回の操作を 1 回の Undo で戻す」約束も割れるためである。
- 放置時: 引き継がない（記録だけ）。

## 選択肢と裁定

- A: 引き継がない。現状を仕様として記録する（却下 — ユーザーは複製ごとに選びたい）
- B: 常に引き継ぐ（却下 — タグが要らない複製でも毎回外す手間が出る）
- C: 複製するときに、タグを引き継ぐかをパネルなどでその場で選べるようにする（**採用** — ユーザー回答 2026-09-26「Tag の引継ぎは複製するときにパネルか何かで選択できるようにする」。A でも B でもない選択肢としてユーザーが示した）

## 波及

- 第 2 期の Scope 外なので、実装は #2005（section:schedule）で行う。#2005 は計画書 P6 の着地を前提にする。P6 も同じ `handleDuplicate` を書き換えるためである。
- 選ぶ UI の形（右クリックメニューを 2 項目に分ける、複製前の小さいパネルでチェックを付ける、など）は #2005 の実装側が案を出し、PR で見せる。
- 引き継いだタグも含めて Ctrl+Z 1 回で複製がまるごと戻ることを #2005 の DoD にした。
