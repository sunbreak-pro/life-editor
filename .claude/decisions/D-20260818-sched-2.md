# D-20260818-sched-2: narrow の Schedule → Todo タブでハンバーガーが空のドロワーを開く件

## 背景

（キュー原文 = `comm/decisions/chat-schedule-refine.md`）

- #1033（PR #1081・merge 済み）で descriptor を `tabs+hamburger` にした結果、ハンバーガーが narrow の schedule 2 タブ両方に出る。Calendar タブはドロワーを埋めるが Todo タブは埋めない（`KanbanView` が `RightSidebarPortal` を `isWide` で囲っている。#470 が narrow の Todo 詳細をボトムシートへ回したため）。押すと `detailPanel.empty`「表示する詳細はありません」が出る
- A: このまま受け入れる（推奨）
- B: `narrowHeader` をタブごとに解決できるようにする（約 6 行）
- 放置時: A（現状維持）
- 期限感: いつでも

## 選択肢と裁定

- A: **このまま受け入れる**（**採用** — ユーザー回答 2026-08-19）。理由: 差分ゼロ。ハンバーガーは「セクションのクローム」という設計 SSOT（IA.md）の扱いと一致し、タブを Calendar へ戻せば中身が入る。空表示は無反応ではなく明示のメッセージが出る
- B: タブごとにヘッダーを解決する（却下 — Issue が求めていない新しい仕組みを、見た目の端の話のために 1 枚足すことになる）

## 却下案が復活する条件

- 「タブごとにクロームが違う」ケースが schedule 以外にも現れ、分岐が 2 箇所以上になったとき

## 波及

- なし（#1081 merge 済みのまま）
