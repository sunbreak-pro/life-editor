# D-20261008-main-1: life-editor と拡張アプリの役割分担、数値の記録の置き場、作る順番、読む場所と登録する場所

## 背景

キュー原文なし。2026-10-08 のチャットでこうだいさんが構想を出し、Claude が意見を返し、こうだいさんが「その方向性で OK」と答えたうえで要件 2 つ（Analytics に収集と一覧、leftSidebar に拡張アプリのタブ）を足した。その会話から再構成した。

こうだいさんの構想（原文の要旨）: life-editor の役割は、出来事の保管と、それをもとに次に行うことの分析と、その分析をもとに次のタスクや Todo を作ること。急に入った予定や Todo も一元管理する。このアプリを軸に、家計簿やその他の数値化できる情報を記録し、分析し、毎日の行動や出来事を蓄積する。家計簿などの数値を集めるのは拡張アプリとして作る構想がある。

前提になっている決定: 拡張アプリは別リポジトリに作り窓口を通す（2026-10-06・D-20261007-main-3 = A）。NG-3 は「life-editor 本体に専用 UI を作らない」と読み、V3 の家計簿の例は拡張アプリに置き換える（D-20261007-main-1 = A）。汎用 Database は凍結のまま（D-20260704-main-1）。Analytics は配線・開発を凍結中（`archive/2026-07-16-loop-friction-fixes.md` 決定 6）。

## 選択肢と裁定

**Q1: life-editor と拡張アプリの役割分担**

- A: life-editor は出来事を貯め、読み、次の Todo に変える本社。拡張アプリは数値を集めて上げるだけの支店で、判断を持たない（**採用** — ユーザー回答 2026-10-08「その方向性で OK」。Briefing ループ（`2026-07-15-briefing-loop.md` §1〜§2）の 5 つの動詞のうち「分析」の材料を太くする位置づけ）
- B: 拡張アプリも独自に分析と Todo 作成を持つ（却下 — 分析の出口が 2 つになり、「ループの 5 動詞に仕えるか」の判定基準から外れる）

**Q2: 数値の記録の置き場**

- A: life-editor の共通テーブル 1 つ（`app_records`）。`items_meta` の外の独立テーブルで、追記専用、種類は値（`kind`）で持つ。0018 の timer 系と同じ扱い（**採用** — ユーザー回答 2026-10-08。タグ・リンク・ゴミ箱の対象にならない行に 2 行分割の仕組みは要らない）
- B: 種類ごとにテーブルを分ける（却下 — 種類が増えるたびに DDL と db push が要る）
- C: 凍結中の汎用 Database を解凍して載せる（却下 — D-20260704-main-1 / D-20261007-main-1 で凍結のまま）
- D: 拡張アプリ側の DB に置き、life-editor は参照だけ（却下 — 分析の材料が本社に貯まらない。Supabase の無料枠は 2 プロジェクトまで）

**Q3: 作る順番**

- A: データの仕組み（テーブル + MCP の道具）を先に作り、スマホの Claude から記録して 2〜3 週間使う。入力専用の拡張アプリ（家計簿）はそのあと（**採用** — ユーザー回答 2026-10-08。「数値を貯めれば分析が役に立つ」はまだ確かめていない。D-20261002-briefing-3 と同じ順番）
- B: 家計簿アプリを先に作る（却下 — 数か月かかる前に、役に立つかを確かめる）

**Q4: 読む場所と登録する場所**

- A: 収集した数値の一覧と集計は Analytics の「記録」タブ（既存 4 タブは凍結のまま、記録タブの分だけ凍結を解く）。拡張アプリの登録と一覧はサイドバーの新しいセクション Apps（**採用** — ユーザー指定 2026-10-08「Analytics のほうに拡張アプリからのデータの収集、一覧化などを実装する」「leftSidebar に拡張アプリとして登録、追加したアプリが一覧化できるタブを新しく作成する」）
- B: 拡張アプリの一覧を Settings の AI 連携カードに置く（却下 — ユーザー指定で新しいタブ。鍵の一覧（#2146 の後続）の置き場は未決）
- C: 記録も一覧も専用の新セクション 1 つに置く（却下 — Analytics が受けるとユーザー指定）

## 却下案が復活する条件

- Q2-B: 1 つの種類に専用の列や集計が必要になったとき
- Q2-C: 移行の完了後に、こうだいさんが改めて汎用 Database を望んだとき
- Q4-B: Apps の行が 1〜2 件のまま増えず、セクション 1 枠が重いと分かったとき
