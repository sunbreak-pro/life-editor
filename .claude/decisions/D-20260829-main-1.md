# D-20260829-main-1: 配布方針を N=1 から限定人数配布へ転換するか

## 背景

（キュー原文なし — 2026-08-29 の配布品質監査セッションでの対話裁定を、memory/chat-main.md の同日エントリと Issue #1202 本文から再構成した事後記録）

配布品質監査（Web 完結・2026-08-29）で、実装が「RLS owner-only + 公開サインアップ」である一方、CLAUDE.md は「ユーザーは作者本人のみ（N=1）」「Cloud Sync = 作者本人のみ（友達ビルドは feature flag で無効）」と主張しており、しかも friend-build feature flag はコードに実在しない（grep 全滅）ことが判明した。docs とコードのどちらへ寄せるかのユーザー裁定が必要だった。

## 選択肢と裁定

- 限定人数配布（**採用** — 2026-08-29 ユーザー裁定）: 公開 Web URL を限定人数へ配布する。無料枠の見立てで安全圏 = 10〜20 人。サインアップは開放のまま、メール確認は実装（#1197 → PR #1219）、プライバシーポリシー / 利用規約は作成（#1198 → PR #1222）。ユーザー間のデータ分離は RLS owner-only が担う
- N=1 へ戻す（却下）: サインアップを閉じて docs の旧記述へコードを合わせる案。配布の意図と逆行するため不採用
- feature flag の新設（却下）: 旧記述どおり友達ビルド用 flag を実装する案。存在しない機構を後追いで作ることになり、限定配布の実態（同一ビルド・同一 URL）に合わない
