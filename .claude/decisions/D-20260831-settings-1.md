# D-20260831-settings-1: Claude Code 起動導線の置き場・起動形態・起動フォルダをどうするか

## 背景

計画書 `2026-08-29-claude-launcher-desktop.md` の Step 0（🛑 人手ゲート）。CLAUDE.md §5 が「ターミナル退役後の常設起動導線は生成デザイン確定後に再設計」としており、その再設計そのものに当たるため、実装前にユーザー確認を必須としていた。

計画書は「Settings カード内ボタンのみで開始 / OS の新規ターミナルで `claude "<prompt>"`」を提案していた。実装前調査で **起動フォルダが未定義だと機能が成立しない**ことが判明したため、この 1 問を足して 3 問で確認した — `claude` は起動ディレクトリの `.mcp.json` から MCP サーバーを読むので、任意の場所で起動すると life-editor のデータに繋がらない Claude が立ち上がる。

## 選択肢と裁定

**Q1. 起動ボタンの置き場**

- A: AI 連携カード内のみ（計画書の既定・Scope 内）（却下 — 導線が Settings を開かないと辿れない）
- B: **カード内 + サイドバー下部に常設**（**採用** — ユーザー回答 2026-08-31。どの画面からも 1 クリックで起動できる。Scope 外の `SidebarNav` / `AppShell` / `MainScreen` を触ることをユーザーが承知のうえで選択）
- C: 独立カードを新設（却下 — Settings が縦に伸びるだけで導線は増えない）

**Q2. 起動時に渡すプロンプト**

- A: **何も渡さず素の `claude` を起動**（**採用** — v1 で一番壊れにくい。IPC 引数にユーザー自由文字列が乗らないため、OS コマンドへ渡る文字列がフォルダパス 1 本に減る）
- B: 定型の書き出しを渡す（却下 — 文面が合わない日に消す手間。v2 候補）
- C: 入力欄を置いて打った文を渡す（却下 — renderer の自由文字列が OS コマンド経路に乗る。必要になってから足す）

**Q3. ターミナルを開くフォルダ**

- A: **Settings に「プロジェクトのパス」欄を追加してそこで起動**（**採用** — MCP に繋がる唯一の選択肢。IPC が 1 本増えるが #529 の上限 10 内）
- B: ホームディレクトリ（却下 — MCP に繋がらず「Claude をとりあえず開く」だけの機能になる）
- C: アプリ実行ファイルの場所（却下 — 同上。パッケージ版では repo と一致しない）

## 却下案が復活する条件

- Q2-B / Q2-C: v1 の素起動が定着し、毎回同じ書き出しを手で打っている実感が出たら
- Q1-A: サイドバー常設行が「使わないのに常に見えている」と感じられたら（行を落として カード内のみへ戻す）

## 波及

- 計画書 Scope に `SidebarNav.tsx` / `AppShell.tsx` / `MainScreen.tsx` / `useShellChrome.tsx` を追加（Q1-B の帰結）
- 計画書 Step 1 の「exposed count 7→8」は **7→9** に変更（Q3-A が `claude:getProjectPath` を要求。上限 10 は維持）
- 計画書 Step 2 の「プロンプトを検証」は不要になり、代わりに**フォルダパスの検証**が同じ役割を負う（Q2-A + Q3-A）
