# D-20260902-main-1: #1373 で凍った進捗の数字 2 つ（「今日の流れ」カウンタ / ルーチン進捗バー）をどう扱うか

## 背景

（キュー未提出のまま AskUserQuestion で回答が先行したため、Issue #1440 と schedule-refine の outbox 2026-09-01 から再構成）

#1373（PR #1424・merged）で予定から完了概念を全部外した結果、**Event 由来の完了数を数えていた表示 2 つが動かなくなった**。撤去そのものは Issue の要求どおりで、残ったのは仕様の判断。

| 止まるもの                      | 出る場所                                  | 撤去後の見え方                            |
| ------------------------------- | ----------------------------------------- | ----------------------------------------- |
| `{done}/{total}` カウンタ       | Schedule サイドバーの「今日の流れ」見出し | Event 分が常に done=0 で数えられる        |
| `RoutineSummaryCard` の進捗バー | Desktop サイドバーのルーチン集計          | 生成された Event が完了しないので伸びない |

データと書き込み経路は温存してある — `completed` / `completed_at` 列も MCP の `set_schedule_complete` も残っていて値は今も入る。画面の入口が消えただけ。

## 選択肢と裁定

- A: 数字を **Todo 由来だけ**に寄せる（**採用** — ユーザー回答 2026-09-02 AskUserQuestion・chat-main 代行。Event を分母からも外し、「今日の流れ」= Todo の消化率にする。完了概念を持つのは Todo だけ、という #1373 の方針と揃う）
- B: 別の指標に替える（例: 開始時刻を過ぎた件数 / 全件）（却下 — 指標の定義を新たに 1 つ決める必要があり、#1373 が畳んだ「予定の状態」を別の形で再導入することになる）
- C: 表示ごと畳む（却下 — 最小の変更だが、サイドバーから「今日の進み具合」が消える）

## 却下案が復活する条件（任意）

予定リマインダー（#1374）が着地したあとで「予定がどこまで進んだか」を時刻で表す需要が出たら、B を別 Issue として起票する。
