# D-20260829-web-1: Supabase の「Confirm email」を ON にするか

## 背景

（キュー原文 — 回答に伴い本 PR でキューから削除）

#1197（PR #1219）。コード側は ON / OFF どちらでも壊れない形にした（`signUp` の戻り値の形だけを見ており、プロジェクト設定は読んでいない）。実際に確認メールを必須にするのはダッシュボードの Authentication → Sign In / Providers → Email → Confirm email で、これはユーザーの手番。

## 選択肢と裁定

- A: ON にする（**採用** — ユーザー回答 2026-08-30 AskUserQuestion。第三者配布で、実在しないアドレスでの登録を止められる。**ダッシュボードの切替は 2026-08-30 にユーザーが実施済み**）
- B: OFF のまま（却下 — サインアップ即ログインは配布方針転換（D-20260829-main-1）後の第三者受け入れと整合しない。実装が両対応なので OFF でも壊れはしない）

## 却下案が復活する条件

- Supabase 内蔵の送信元は 1 時間あたりの通数制限が厳しいため、本格配布で通数が問題になり独自 SMTP を用意できない期間は一時的に OFF へ戻す余地がある（本格配布時は独自 SMTP の用意を先に検討する）

## 波及

- Supabase ダッシュボード設定（Confirm email = ON・2026-08-30 ユーザー実施済み）
- 本格配布前の独自 SMTP 検討（未着手・必要になった時点で Issue 化）
