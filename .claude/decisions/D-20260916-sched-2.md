# D-20260916-sched-2: 繰り返しアイテムで「範囲」を聞く操作を、どこまで広げるか

## 背景

（キュー原文 — 回答に伴い本 PR でキューから削除。起票 = chat-schedule-refine / PR #1653）

- 背景: #1642 工程 1 の棚卸し E-01〜E-09。今は同じ「行を動かす操作」でも、タイトル・時刻の編集と同じ日の中のドラッグは 3 択を聞き、日付だけの変更・終日切替・別の日へのドラッグ・頻度変更・「なし」に戻すは黙って適用される（`eventEditorSave.ts:52-64`・`useScheduleMutations.ts:294-298`・`useRepeatMutations.ts:252-341`）。聞かない側にはコード内に個別の理由が書かれており、仕様の是非はユーザー判断
- 放置時: W6 に着手しない。#1638（全変更を Undo 可能にする）の確認ダイアログは、現在聞いている経路だけを対象に実装する
- 期限感: 工程 2 の W6 着手前まで

## 選択肢と裁定

- A: 現状維持（**採用** — ユーザー回答 2026-09-16「推奨のままで OK」。現在の「聞く / 聞かない」をそのまま仕様として計画書に固定し、実装は揃えない）
- B: 行を動かす操作はすべて聞く（却下 — 日付変更・終日切替・別の日へのドラッグまで 3 択を挟むと、単発の移動のたびにダイアログが出る。聞かない側にはコード内に個別の理由がある）
- C: 中間。シリーズ全体に効く 2 つ（頻度変更・「なし」に戻す）だけ聞く（却下 — A より良い保証が無く、挙動変更ゼロの原則から外れる）

## 却下案が復活する条件

「勝手にシリーズ全体が変わった」という誤操作が実利用で出たとき。その時点で C（シリーズ全体に効く 2 つだけ聞く）から再検討する。
