# D-20260809-main-1: 決定台帳（decisions/）を新設し「ADR は作らない」方針を SUPERSEDE するか

## 背景

`.claude/` 記録システムの全数調査（2026-08-09・remote セッション）で、設計判断の「なぜ・却下案」が構造的に残る場所が 3 箇所しかなく（キューの A/B 定型・plans 決定録・archive/SUMMARY の採否凡例）、うちキューは**回答後にエントリを削除する**プロトコルのため思考過程が消えることが判明した。理由の多くは memory の 400B 超 bullet（3 件枠で押し出される・ブランチ跨ぎで衝突する最揮発層）か GitHub Issue コメント（リポジトリ単体で到達不能）に埋まっている。

一方、旧 ADR は「時点判断で陳腐化する」を理由に廃止済み（`archive/SUMMARY.md` Lessons）で、その廃止理由自体が参照切れになっていた（CLAUDE.md は `coding-principles.md` 冒頭を指すが、冒頭に理由は書かれていない）。

## 選択肢と裁定

- A: **台帳新設で SUPERSEDE**（**採用** — ユーザー回答 2026-08-09）。既存キューの A/B 定型を「回答後も消さず 1 決定 1 ファイルで台帳化」する形に昇格する。旧 ADR の陳腐化問題には**上書きでなく supersede 連鎖**（`supersedes` / `superseded-by` の双方向リンク + INDEX が連鎖の末端だけを Active 表示）で対処する — ファイルは書き換えず追加で鮮度を表現するため、「古い記述が現行に見える」ADR の失敗様式が構造的に起きない
- B: 既存の枠内に留める（却下 — plans 決定録と coding-principles への追記を徹底する運用強化のみでは、計画を跨ぐ判断・キュー消化後の Why が引き続き無索引のまま残る）

## 波及

- `comm/decisions/README.md`「回答済みエントリの削除」→「台帳へ昇格してから削除」に更新
- `rules/decision-queue.md` に昇格手順を追記・`rules/records.md`（書き込み先の判定表）を新設
- CLAUDE.md §9 / `skills/docs-workflow/SKILL.md` の「ADR は作らない」行を本裁定参照に書換え
