# D-20260830-main-1: 退役レーンの memory を chat-main が畳んでよいか（単一書込者ルールの例外）

## 背景

（キュー原文 — 回答に伴い本 PR でキューから削除）

#1135。`memory/chat-*.md` は 34 本あるが worktree があるのは 13 本で、残り 21 本は単一書込者ルール（`comm/README.md`）により**誰も直せず凍っている**。INDEX の「進行中」11 件中 9 件が決着済みのまま残り、レーン手番の判定材料が機能していない。受け皿の機構（`> RETIRED:` マーカーを「進行中」集計から外す）は PR #1295 で先行実装済み — マーカーを 1 本も付けなければ何も変わらない不活性な状態だった。

## 選択肢と裁定

- A: chat-main に退役操作の権限を認める（**採用** — ユーザー回答 2026-08-30 AskUserQuestion）: `comm/README.md` に「worktree を持たないレーンの `chat-*.md` へ chat-main が RETIRED マーカーを付けてよい」を明文化 → 該当 21 レーンにマーカー付与。履歴はファイルごとその場に残る
- B: `history/archive/` へ物理移動（却下 — 進行中からは消えるが、ファイルの置き場が変わり既存の参照リンクが切れる）
- C: 現状維持（却下 — INDEX の stale を受け入れ issue-prompter の注意書き = PR #1282 だけで運用する案。判定材料の壊れが直らない）

## 却下案が復活する条件

- B: 退役ファイルが増えすぎて `memory/` の一覧性を損なうようになったら、マーカー付きファイルの一括 archive 移動を再検討する

## 波及

- `comm/README.md` §中核ルール（例外の明文化）
- `memory/chat-*.md` 21 本（マーカー付与）
- `.claude/scripts/hooks-lib/regen-index.sh`（vendor — 集計スキップ）。repo 外の `$HOME/dev/Claude/hooks-lib/regen-index.sh` は別対応（同じスキップ処理の追随が要る）
