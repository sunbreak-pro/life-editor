# D-20260815-briefing-7: 目標欄に保存状態のフィードバックを付けるか

## 背景

（キュー原文 = `comm/decisions/chat-briefing-refine.md` をそのまま貼る）

- 背景: #872 の実装中に浮上（PR #914 着地済み・未実装）。宣言は見出しの右に「保存済み / 未保存」を出すが、目標はそのスロットを期間ラベル（`8/10 – 8/16` 等）が使っているため出していない。結果として**目標では保存の失敗を知る手段がゼロ**になる（`useGoalsDoc` の catch は `console.error` のみ）。draft は画面に残るのでリロードするまで気付けず、そこで消える。なお既存の `useDailySections`（宣言・夕刊）も保存失敗を飲み込む同じ性質なので、これは回帰ではなく元からの穴
- A: 目標だけキャプションを足す（期間ラベルの下に小さく出す or ラベルと入れ替える。目標の穴は塞がるが、同じ穴が残る宣言側と作りが揃わない）
- B: 保存失敗を Toast で拾う仕組みを紙面全体（宣言 / 夕刊 / 目標）に入れる（推奨 — 穴の本体は「失敗が無音」であって「キャプションが無い」ではない。ただし別 Issue の規模）
- 放置時: 現状維持（無表示のまま）。#872 の PR は既に出しているのでこの判断でブロックしない
- 期限感: いつでも（B に倒すなら別 Issue へ）

## 選択肢と裁定

- B: 保存失敗を Toast で拾う仕組みを紙面の書き込み 3 経路（宣言 / 夕刊 / 目標）にまとめて入れる（**採用** — ユーザー回答 2026-08-16。穴の本体は「失敗が無音」であってキャプションの不在ではない）
- A: 目標だけキャプションを足す（却下 — 目標の穴は塞がるが、同じ穴が残る宣言・夕刊側と作りが揃わず、無音の失敗という本体が残る）

## 波及

- 実装 Issue = **#955**（`section:briefing` / `type:bug` / `sev:minor`）
- 3 経路が同じ仕組みを共有し、今後増える書き込み経路も同じ形で載せられることを DoD に含める
- 既存の Toast（Tier 2）に載せる。新しい通知機構は作らない
