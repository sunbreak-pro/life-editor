# D-20260928-briefing-3: Claude を繋いでいない配布先の人に、Briefing をどう見せますか

## 背景

（キュー原文 — 回答に伴いこの PR でキューから削除。起票 = chat-briefing-refine）

- 背景: 配布先（10〜20 人）は今の仕組みでは自分のデータに Claude を繋げません。MCP サーバーは環境変数のメールとパスワードで 1 人としてログインし（`mcp-server/src/supabase.ts:65`）、Remote MCP も共有の合言葉 1 本です。いまの紙面で Claude が埋めるのは講評とフォーカスだけで、講評は空なら枠ごと消えるため、残りのブロックはアプリとユーザーの入力で埋まります。
- A: Claude が居なくても完結する画面を基本にし、Claude の部分は付いていれば出るおまけにする。
- B: Claude を繋ぐ前提の画面にし、繋いでいない人には「繋ぐとここが埋まります」の案内を出す。
- C: 配布先には今の紙面をそのまま出す（配布先向けの作り分けはしない）。
- 放置時: 見え方は今のまま据え置きます。コンセプトの選択は回答待ちのまま置きます。
- 期限感: D-20260928-briefing-4 と同時で構いません

## 選択肢と裁定

- A: Claude が居なくても完結する画面を基本にし、Claude の部分は付いていれば出るおまけにする（**採用** — ユーザー回答 2026-09-30 のチャット）。D-20260928-briefing-4 で決めた設計では、目標・進み具合・夕刊の記録・「明日の自分へ」がすべてユーザーの操作で埋まります。Claude が書くのは朝刊の講評だけになるので、この形と合います。
- B: Claude を繋ぐ前提にし、繋いでいない人に案内を出す（却下 — 配布先の人は今の仕組みでは自分のデータに Claude を繋げないため、案内を出しても埋める手段がありません）。
- C: 配布先向けの作り分けをしない（却下 — 新しい設計に作り直すので、今の紙面をそのまま出す前提が消えます）。

## 却下案が復活する条件

人ごとのログイン（OAuth）で、配布先の人も自分のデータに Claude を繋げるようになったとき。そのときは B の「繋ぐとここが埋まります」の案内を足すかを改めて判断します。

## 波及

- Claude Design への依頼文（`.claude/docs/design/briefs/briefing.md` の §3 の枠「10.5」）は、すでにこの形で書いてあります。Claude の講評が無い日を、欠けた画面に見せない依頼です。
- 朝刊の講評の枠は、今と同じく書かれた日だけ出します。
