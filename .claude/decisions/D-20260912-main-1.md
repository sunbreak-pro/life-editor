# D-20260912-main-1: Connect（つながり）を読むだけの Tag hub から「タグとリンクの編集所」へ作り替えるか

## 背景

ユーザー提起（2026-09-12）: 「現状は Tag による一覧化による表示でしかなく、それなら Tag の編集と統合させたほうが良いと感じる。また、リンク機能も可視化したいがそれもできていない。UI / UX も微妙である。まず Connect の機能をもう一度考え直して、必要・不要な機能を考えたい。その後 ClaudeDesign で UI / UX を作成するためのプロンプトを作成する」。

棚卸しと本番 DB の実測（2026-09-12・レポート = `docs/reports/2026-09-12-connect-redefinition.html`）で 3 点が出た。

1. タグ一覧を読む画面が 3 つある（Connect / タグ編集モーダルの所属一覧 / Notes のタグ見出しリスト）。編集できるのはモーダルだけ
2. イベント 90 件のタグ付けが 0 件・未分類が 150 件中 133 件。付ける導線が「1 件ずつ詳細を開く」しか無い
3. アイテム間リンクは生存 4 本。張れる UI がノート詳細の LinkPanel だけで、可視化する材料が育っていない

## 選択肢と裁定

**Q1 統合の範囲**

- A: タグ編集モーダルを退役して Connect に一本化する（**採用** — ユーザー回答 2026-09-12。同じタグ一覧が 2 画面ある状態を畳み、改名 / アイコン / 色 / 削除 / 統合 / 一括の付け外しを Connect 内で完結させる）
- B: モーダルを残し Connect 側にも編集を足す（却下 — 入口が 2 つ残り、同じ一覧の二重保守が続く）
- C: Connect は読み取りのまま（却下 — 提起された重複がそのまま残る）

**Q2 リンクの置き場**

- A: 詳細パネル（右 320px）で選択アイテムの近傍を出す（**採用** — ユーザー回答 2026-09-12。リンク / 同じタグのアイテム / 同じ日のデイリーの 3 節 + リンク追加。タブを増やさず、空だった右パネルに役割を与える）
- B: Connect の 2 つ目のタブとして立てる（却下 — 単画面構成を崩し、リンク 4 本に対して画面 1 枚は重い）
- C: 今回は触らない（却下 — 提起の半分が残る）

**Q3 ClaudeDesign に出す範囲**

- A: Desktop と Mobile を同時に出す（**採用** — ユーザー回答 2026-09-12。Mobile のタグ管理は #1290 で Full 確定済みのため、後から設計し直す手戻りが大きい）
- B: Desktop だけ先に出す（却下 — 同上）

## 却下案が復活する条件

- Q2-B（リンク軸を独立させる）: アイテム間リンクが育って 1 枚の画面に値する本数（目安 50 本以上）になり、「最近つないだリンク」「リンク 0 件のアイテム」の一覧を読みたくなったとき
- 力学グラフの復活は本決定の対象外（#1152 / D-20260829-connect-1 を覆さない）
