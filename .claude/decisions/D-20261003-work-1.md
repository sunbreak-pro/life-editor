# D-20261003-work-1: Work の Mobile ドロワーの設定は、− / + を押すたびに保存するか、今の保存ボタンを残すか

## 背景

（キュー原文 — 回答に伴いキューから削除。起票 = chat-work-refine）

- 背景: #2054（Claude Design の A 案）。案は − / + だけで保存ボタンを描いていない。PR #2071では保存ボタンを残し、− / + は下書きを変えるだけにした（#714 の「1 回の押下で 1 回だけ保存」のまま）。`shared/src/components/PomodoroSettings.tsx` の drawer 分岐
- 放置時: A のまま（PR の実装どおり）。B に変える作業は始めない
- 期限感: いつでも（PR の merge を止めない）

## 選択肢と裁定

- A: 保存ボタンを残す（**採用** — ユーザー回答 2026-10-03 / 押すたびの保存は同期が何度も走り、取り消し履歴も押した回数ぶん積まれる。Desktop と保存の型がそろう）
- B: 押すたびに保存し、保存ボタンを消す（Mobile のみ。案どおりの見た目になる）（却下 — 上の理由）

## 却下案が復活する条件

設定の保存を数百ミリ秒まとめて 1 回にする仕組み（debounce）が入り、同期と取り消し履歴が押した回数ぶん積まれなくなったとき。

## 波及

コードの変更は無い（PR #2071 の実装のまま確定）。
