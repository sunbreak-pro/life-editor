# D-20260802-sched-1: outbox エントリを実装 PR に同梱するか、tracker と同様に merge 後へ回すか

## 背景

（キュー原文 = `comm/decisions/chat-schedule-refine.md`）

D-20260801-main-1 は tracker（memory/history）を実装ブランチに載せないとだけ規定していて、`.claude/comm/outbox/` の扱いは未規定。outbox も「同じファイルの先頭への追記」なので、複数ブランチが並行すると tracker と同じ衝突パターンになる。今セッションは #555 / #551 / #553 の 3 本を同一 worktree から連続して出すため、各 PR に outbox エントリを載せると 2 本目以降が必ず衝突する。

## 選択肢と裁定

- A: 実装 PR に同梱する（従来型）。エントリがその PR と一緒に main へ届く（却下 — chat-main が merge 時点で起票依頼まで読めるのは利点だが、並行 PR で outbox が衝突する。tracker で実証済みのパターン）
- B: **tracker と同じく実装 PR では触らず、別枠でまとめて 1 commit**（**採用** — ユーザー回答 2026-08-12）。それまで worktree の作業ツリーに未コミットで保持する
  - 利点: 衝突ゼロ。D-20260801-main-1 と一貫
  - 欠点: chat-main への伝達が遅れる（緊急の連絡は PR 本文 / PR コメントに併記して補う）

## 波及

- `.claude/CLAUDE.md` §7.4 の「tracker を実装ブランチに載せない」箇条に、outbox も同じ扱いである旨を 1 行追記
