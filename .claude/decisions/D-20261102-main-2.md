# D-20261102-main-2: merge-round で衝突を減らす次の段をどれにするか

## 選択肢と裁定

- **B（採用）**: 機械的に解ける衝突は chat-main が直す。対象は、衝突が文書（`.md`）・lockfile・翻訳ファイル（`i18n/locales/*.json`）だけで、CI が赤くなく、どのレーンもそのブランチを開いていない PR に限る。サブエージェント（Sonnet）が一時 worktree で解き、`autofix-push` が「変わったのは衝突したファイルだけ」「衝突の印が無い」「JSON が読める」「その間にレーンが push していない」を確かめてから fast-forward で push する。
- GitHub Agent Merge を試す: 見送り。Copilot の有料プランが別に要るため。
- 今の形（回ごとの指示文）で手間を測る: 見送り。

2026-11-02 にこうだいさんがチャットの AskUserQuestion で推奨どおり B を選んだ。

## 決まりごと

- レーンが開いているブランチには chat-main は push しない。同じブランチに書き手が 2 人いると、レーンの手元と push がずれるためです。
- force push はしない。push は fast-forward だけにする。
- 直せなかった PR は `autofix-abort` が先頭を覚え、同じ先頭のあいだはレーンへの `/goal` に回す。
