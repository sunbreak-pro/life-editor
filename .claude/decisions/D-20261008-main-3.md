# D-20261008-main-3: 本文からフォーカスが外れたあと、ヘッダーの Undo / Redo がどの履歴を動かすか

## 背景（質問の原文）

#2141 の不具合への対応です。本文エディタはフォーカスを失うと自分の履歴をヘッダーから引き上げます（#1690 の仕組み）。このため、キーボードを閉じたあとはヘッダーの Undo / Redo が空のアプリ全体の履歴を見て押せなくなります。直すにあたり、本文の変更とアプリの操作（タグの付け外しなど）が混ざったとき、どちらを戻すかを決める必要がありました。

例として、Note の本文に「abc」と入力し、キーボードを閉じ、タグ「仕事」を付けてから、ヘッダーの Undo を押す場合を示しました。

Q1: 本文からフォーカスが外れたあと、ヘッダーの Undo / Redo はどの履歴を動かすか。Desktop で本文の外にいるときの Ctrl+Z も同じ動きにそろえる。

- A: 本文エディタが画面にある間は、常に本文の履歴を動かす。1 回目で「abc」が消え、2 回目は押せない。タグはヘッダーから外せない。実装はいちばん軽い。
- B: 本文の変更とアプリの操作を時系列で並べ、新しいものから戻す。1 回目でタグが外れ、2 回目で「abc」が消える（推奨）。2 つの履歴の順番を記録するしかけが要るので、実装はいちばん重い。
- C: 本文に戻せる変更があれば本文を先に戻し、本文の履歴が空になったらアプリの操作を戻す。1 回目で「abc」が消え、本文を開いた時点まで戻したあとにタグが外れる。

Q2: Mobile の「その他」シートの Undo / Redo（今はアプリ全体の履歴だけを動かす）も、ヘッダーと同じ動きにするか。

- A: ヘッダーとそろえる（推奨）。#2141 の Scope に `web/src/MobileShellActions.tsx` を足す。
- B: 今のままにする。

## 裁定

Q1 = B（**採用** — ユーザー回答 2026-10-08、チャットの選択式の質問）: 本文からフォーカスが外れたあとは、本文の変更とアプリの操作のうち新しいほうから戻す。Redo も同じく、直前に戻したほうから進める。Desktop で本文の外にいるときの Ctrl+Z も同じ動きにする。本文にフォーカスがあるときの動き（#1690 = 本文の Ctrl+Z とヘッダーの Undo が本文の履歴を動かす）は変えない。

Q2 = A（**採用** — 同上）: Mobile の「その他」シートの Undo / Redo もヘッダーと同じ動きにする。

却下: Q1-A はタグや改名をヘッダーから戻せなくなるため、Q1-C は戻る順番が操作した順番と食い違うため、採らなかった。
