# D-20261017-main-1: 記録の平均と最新を足し、種類ごとに選んだ表示をどこに置くか

## 背景

キュー原文なし。計画書 `2026-10-12-records-aggregation-views.md` の「着手前に決めること」3 問を、2026-10-17 のチャットでこうだいさんが「#2231 の計画書を承認する」と答えて決着させた。回答は 1 つで、3 問を個別には答えていない。そのため、3 問とも計画書が示した推奨を採ったものとして記録する。

動機は、体重のように「その時点の値」を残す記録では合計に意味がないこと。#2212 の実ブラウザ確認で、Mobile の記録ブロックが「weight · 2 records 124.5 kg」と足し算を出していた。2026-10-12 にこうだいさんは、平均と最新の値を両方出せるようにすることと、記録の種類ごとに表示を選べるようにすることを決めている（#2231）。

## 選択肢と裁定

### Q1 選べる表示の中身

- 値の出し方（合計 / 平均 / 最新 / 件数）と、グラフの形（棒 / 折れ線）の両方を選べる（**採用** — 2026-10-17 の承認 / 体重は折れ線のほうが傾きが読める）
- 値の出し方だけ選べて、グラフは棒のまま（却下 — 折れ線の部品を作らない分だけ差分は減るが、傾きが読めない）

### Q2 選んだ内容の置き場所

- 専用の設定表 `record_views`（キー = 種類 + 単位）を足し、DB に保存して同期する（**採用** — 2026-10-17 の承認 / Desktop と Mobile で選んだ表示がそろう。`claude` 由来の種類にも置ける）
- この端末の `localStorage` に保存する（却下 — 端末ごとに違う値になる。公開 Web URL が主導線なので、ブラウザを変えると「選んだのに戻っている」と見える）
- `extension_apps` に JSON 列を足す（却下 — 台帳に行がない `claude`（MCP から入れた記録）と、記録だけ届いているアプリの種類は、選んだ内容を置けない）

### Q3 初期値

- 選んでいない種類は、すべて「合計」で出す（**採用** — 2026-10-17 の承認 / 今の表示と同じになる）
- 単位や種類の名前から自動で決める（却下 — 名前の当て推量で、当たらない種類が必ず出る。選べるようにするのが今回の目的）

## 却下案が復活する条件

- `localStorage` 案: 設定表の DDL を出す余裕がなく、まず見た目だけ先に出したいとき
- `extension_apps` の JSON 列案: `claude` 由来の記録を台帳に自動登録する決定が出たとき
- 値の出し方だけの案: 折れ線の差分が 500 行を超えるとき（Step 6 を別 PR に切り出す）
- 名前から自動で決める案: 種類が増えて、毎回選ぶのが負担になったとき
