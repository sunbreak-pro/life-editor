# D-20260818-sched-1: #997 Undo は「変換で破棄したフィールド」まで戻すか

## 背景

（キュー原文 = `comm/decisions/chat-schedule-refine.md`）

- #625 の変換は role を移すだけで、逆変換だけでは戻らない列がある。どちらの方向も新しい payload を古い行から組み立てて**自分を完全に指定した行を UPSERT する**ので、組み立て側が触れていない列は NULL / false で返る（Todo→Event で落ちるのは parentId / priority / color / icon / timeMemo / workDurationMinutes / reminderEnabled / reminderOffset / isExpanded / NULL status、Event→Todo で落ちるのは isDismissed）
- A: スナップショットから全部戻す（推奨）
- B: 逆変換だけ（role・タイトル・メモ・完了・日時のみ）。破棄は破棄のまま = D-20260810-sched-3 の裁定を Undo にも適用
- 放置時: PR #1092 は A で実装済み（安全側）
- 期限感: #1092 の merge 前まで

## 選択肢と裁定

- A: **スナップショットから全部戻す**（**採用** — ユーザー回答 2026-08-19・chat-main が代行して質問 / 転記）。理由: Undo の意味は「変換前の状態に戻す」であり、このスタックの他のコマンドはすべてスナップショット丸ごとを再生している。Undo だけが情報を落とすと、ユーザーから見て「取り消したのに戻っていない」になる
- B: 逆変換だけ（却下 — D-20260810-sched-3 が「変換時に落ちるフィールドは破棄する」と決めたのは**前に進む操作**の話で、巻き戻しに同じ規則を当てる理由が無い）

## 却下案が復活する条件

- スナップショットの保持コストが実測で問題になったとき（現状 N=1・アイテム単位のスナップショットなので考えにくい）

## 波及

- PR #1092（merged）が既に A の形。追加作業なし
