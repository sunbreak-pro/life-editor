# 配布向けに作った 5 つの機能を消すか

## 背景

> キューを経ていません。2026-11-16 に main のチャットが、機能の棚卸し（Issue #2716 の手順 1）の報告のあとに AskUserQuestion で聞いた問いを、そのまま写しました。

- **何が起きているか。** サインアップとメール確認・アカウント削除・利用規約とプライバシーポリシー・ヘルプ・ツアーは、ほかの人に配るために作った機能です。2026-10-22 の決定（個人の道具にする決定 = `D-20261022-main-1.md`）は、これらを「コードに残す」としていました。
- **なぜ決める必要があるか。** 残すと、表を足すたびにアカウント削除の処理 `delete_my_account()` を作り直す手間と、画面の変更にツアーの目印を合わせる手間が、完成まで続きます。
- **推奨と根拠。** 5 件とも消すほうを推奨しました。利用規約の文面とヘルプの問い合わせ先が未決のままで、配布を目標にしないなら決める機会が来ないためです。

## 選択肢と裁定

- 5 件とも消す（**採用** — ユーザー回答 2026-11-16）。サインイン・パスワードの再設定・パスワード変更・サインアウトは残します。
- ツアーとヘルプだけ消す（却下）。認証まわりを今のまま残す案でした。アカウント削除の処理を作り直す手間が残ります。
- 残す（却下）。2026-10-22 の決定のままにする案でした。

## 却下案が復活する条件

配布を再開すると決めたとき。消した機能は git の履歴から戻せます。

## 波及

- 2026-10-22 の決定のうち、個人の道具にすること・配布しないこと・ライセンスは変わりません。置き換えるのは、波及の「配布向けに作った機能はそのまま残します」の 1 行だけです。そのため、元の決定は現在も有効な決定として残します。
- 実装は 5 つの Issue で、同じファイル（`SettingsScreen.tsx`・`AuthScreen.tsx`）を続けて触るので直列に進めます。順番は、ツアーとチュートリアル #2749、ヘルプ #2750、利用規約とプライバシーポリシー #2751、サインアップとメール確認 #2752、アカウント削除 #2753 です。
- CLAUDE.md §1 の「配布向けに作った機能…はコードに残します」の文は、最後の #2753 の PR で直します。
- データの書き出しは決めていません。アカウント削除と同じ表の一覧を使っているので、#2753 で一覧の持ち方だけ直します。
