# D-20260829-connect-1: 退役で呼び出し元ゼロになった backlink 部品 3 つを、このまま保持するか削除するか

## 背景

（キュー原文 — 回答に伴い本 PR でキューから削除）

#1152 / PR #1175。`BacklinkView`（→ `shared/src/components/Backlinks/`）と `backlinkSourceIds` / `resolveLinkId`（→ `shared/src/utils/itemLinks.ts`）は依頼どおり移設したが、削除前の全数 grep で **現行の呼び出し元は Connect 内部だけ**だったことが分かった。Issue 本文の「（LinkPanel が使用）」は実物と異なり、`web/src/wikitag/LinkPanel.tsx:126` は `useWikiTagsUnifiedContext().getLinksForItem()` から自前で読んでいる（`LinkPanel.tsx:52` の言及はコメント内の設計参照）。よって移設後の 3 つは**呼び出し元ゼロ**。

## 選択肢と裁定

- A: 保持する（却下 — 「バックリンクを出す画面」は今後また要るはずで移設済み部品は次のホストの土台になる、という提案側の推奨だったが、tag hub PR #1230 は import しない設計で当面のホストが無い）
- B: 削除する（**採用** — ユーザー回答 2026-08-30。P-002「呼び出し元ゼロの dead code は grep 全数実測を根拠に退役してよい」を適用。実測 = PR #1175 本文 + 2026-08-30 chat-main 再実測。バレル 2 箇所 + LinkPanel のコメント参照も追随 → 実装 Issue #1239 / PR #1258 merged）

## 却下案が復活する条件

- バックリンクを表示する画面を再び作るときは、削除時点のコードを PR #1258 の diff（または git tag `pre-tauri-removal` 以後の履歴）から復元する。データと取り出し口（タグ・アイテム間リンク・`getLinksForItem()`）は #1152 で温存済みなので、UI 部品だけ書き直せばよい
