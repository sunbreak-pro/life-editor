# D-20260804-main-1: Phase 1 定期実行（朝 digest / 夜間安全レーン）の実行基盤をどれにするか

## 背景

親計画 Phase 1（`2026-07-28-loop-engineering-harness.md` §6）のインフラは配置済み（PR = `docs/loop-harness-phase1`）だが、発火の足場が未裁定。実測で、セッション内 scheduled tasks（CronCreate）は**セッション限定 + 繰り返し 7 日期限**と判明し、常駐セッションなしでは毎朝発火に使えない。

## 選択肢と裁定

- A: **Windows Task Scheduler + `claude -p`（headless）**（**採用** — ユーザー回答 2026-08-11。セッション常駐が不要・2026-07-16 の朝刊プロトタイプで同型を E2E 検証済み・digest の正本がローカルファイルである点とも整合。前提 = 06:03 / 22:33 に PC が起動していること。登録コマンドは `automation/routine-ids.md` に準備済み・初回は手動実行で動作確認）
- B: chat-main セッションを常駐させて CronCreate を使う（却下 — 7 日ごとの再登録 + 台帳管理が必要で、セッションを閉じると消える）
- C: クラウド実行（/schedule 系）（却下 — マシン電源に依存しない利点はあるが、親計画 Non-goals「Cloud Routine の復活はしない」と衝突し、ローカルの digest / outbox ファイルに書けない。採る場合は親計画の改訂が先）

## 却下案が復活する条件

PC の起動時刻が安定せず 06:03 / 22:33 の発火が実用にならないと分かった場合は C を再検討する（その際は親計画の Non-goals 改訂が先行条件）。

## 波及

- 無人レーンの柵は runner 側 settings で担保する（`claude -p --settings <無人用>` / `--disallowedTools`）— 対話セッションの `permissions.ask` と兼用しない（D-20260810-main-1 まわりの整理と同じ方針）
- `automation/routine-ids.md` の登録コマンドを実行し、初回は手動実行で動作確認する
