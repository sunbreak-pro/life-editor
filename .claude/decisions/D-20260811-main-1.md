# D-20260811-main-1: Epic #627（保存ボタン統一）の対象範囲をどこで切るか

## 背景

（キュー `comm/decisions/chat-main.md` の原文）

背景: 起票時の下書き 5 行に対し、2026-08-11 の grep 実測で編集面は **19 行**（Note の対象外行を含む）になった。差が 2 行を大きく超えたため、子 Issue の一斉起票を止めてここへ積んだ（実測表は Issue #627 本文が正）。判断が要るのは 3 点 — (1) **Settings 4 パネル**は書き込み先が localStorage で DataService を経由しない（`ThemeContext.tsx:176` / `useDayStartHour.ts:25`）。保存ボタン統一の対象に含めるか (2) **Briefing 2 面**（今日の宣言 / 夜の振り返り本文）は Note・Daily と同じ自動保存系。対象外へ寄せるか (3) **作成専用フォーム**（`ItemCreatePanel` / `TaskAddDialog` / `QuickAddSheet` / `QuickCaptureSheet`）は「既存要素の編集」ではないと判断して表から外したが、含めるか

放置時: 子 Issue を起票しない（Epic #627 は棚卸し済み・fan-out 保留のまま）。段階 1（Schedule の保存ボタン = PR #681）は着地済みなので実害は「横展開が進まない」だけ

期限感: 急がない。ただし各レーンが個別に保存ボタンを足し始める前に決めたい（バラバラの流儀が再生産される）

## 選択肢と裁定

- A: **DataService に書く「既存要素の編集」だけを対象にする**（**採用** — ユーザー回答 2026-08-11）。Settings は localStorage で即時反映が期待される種類の設定、Briefing は Note / Daily と同じ長文自動保存系、作成フォームはもともと「作成」ボタンで確定している。この線なら子 Issue は **Schedule 繰り返し / Tasks の TaskDetailPanel + 本文 / Work の Pomodoro 数値 + AudioMixer / Tags の改名** の 4 本に絞られる
- B: 画面に出る編集はすべて対象にする（却下 — Settings と Briefing も保存ボタンにすると一貫性は最大になるが、Settings のテーマ切替や文字サイズは「押すまで反映されない」体験になり、Briefing は Note / Daily を対象外にした理由と矛盾する）
- C: 段階を分ける（却下 — まず A の範囲で配り Settings / Briefing は別 Epic で後日判断する案。A で対象外の理由が確定したため、保留用の別 Epic を作る必要がなくなった）

## 却下案が復活する条件

- Settings / Briefing の自動保存で「保存されたか分からない」不満が実利用で出たとき（その場合は保存ボタンではなく保存インジケータ側の設計として起票し直す）

## 波及

- Epic #627 の子 Issue は 4 本に確定（Schedule / Tasks / Work / Tags）
- Settings 4 パネル・Briefing 2 面・作成専用フォーム 4 種は Epic #627 の対象外として本文から除外
