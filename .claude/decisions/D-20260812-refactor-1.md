# D-20260812-refactor-1: #726 で `CalendarTab.tsx` に 2 行だけ触れたことの事後確認

## 背景

（キュー原文 = `comm/decisions/chat-refactor-core.md`）

- 背景: レーン指示は「`CalendarTab.tsx` には触らない（schedule-refine が #736 で同じ領域を触っている）」だった。#726 の 12 箇所のうち **11 箇所は shared 側の定数に型を付けるだけで消えた**（`sections.ts` / `types/shortcut.ts` / `constants/sounds.ts` / `components/taskStatusVisuals.ts` / `utils/scheduleLabels.ts`）。MainScreen・SettingsScreen・KanbanView・WorkScreen は 1 文字も変えていない
- 残った 1 箇所だけが `CalendarTab.tsx` の**中で定義された定数** `REPEAT_FAILURE_COPY_KEY`（現 140-143 行）で、外から型を付ける手段が無い。ここを直さないと `cd web && npm run build` が赤のままで、#726 は 1 行も出せない
- 実際に入れた差分は **2 行**: import に `type TranslationKey` を足す（82 行付近）と、`Record<..., string>` を `Record<..., TranslationKey>` にする（142 行）。**挙動ゼロ・ファイル冒頭の定数ブロック**で、#736 が触る TaskDetailPanel の配線（2240 行以降）とは 2000 行以上離れている
- A: **このまま（推奨）** — 型引数 1 個の差し替えなので #736 側と意味的に衝突しない。git も別ハンクとして扱う
- B: この 2 行を PR から外し、#736 の merge 後に別 PR で入れる（その間 #726 は着地できない）
- 放置時: **A のまま**（PR #745 に含まれた状態で出してある ※キュー原文ママ — 実際に 2 行を含めたのは #726 の PR #752。#745 は #736 側の PR）。B にしたい場合は該当 2 行を revert すれば残りはそのまま緑
- 期限感: #726 の PR を merge する前まで

## 選択肢と裁定

> **ユーザー回答ではなく chat-main の裁定**（`status: recorded`）。ユーザー体験が変わる分岐ではなく、レーン運用上の例外可否という技術判断のため（`decisions/README.md` の recorded の条件）。判断の記録は [PR #754 のコメント](https://github.com/sunbreak-pro/life-editor/pull/754#issuecomment-5261134997)にもある。

- A: **例外として認め、2 行を含んだまま #726 を着地させる**（**採用** — chat-main 裁定 2026-08-12）。根拠は 3 つ:
  1. `REPEAT_FAILURE_COPY_KEY` は `CalendarTab.tsx` の中で宣言されており**外から型を付ける手段が無い**。放置すると `cd web && npm run build` が赤のままで、#726 は 1 行も着地できない
  2. 中身は `type TranslationKey` の import 追加と `Record` の型引数 1 つの差し替えだけで、**実行時の挙動は変わらない**
  3. `git merge-tree` で PR #745（#736 の実装）に対して**衝突マーカーゼロを実測**した。#745 の hunk は 1514 行以降、こちらは 82 行付近と 142 行付近で、同じファイルでも触る場所が離れている
- B: 2 行を外し、#736 の merge 後に別 PR で入れる（却下 — 待つ間 #726 が丸ごと着地できず、得られるのは既に「ゼロ」と実測した衝突リスクの回避だけ）

## 波及

**「`CalendarTab.tsx` には触らない」は衝突回避のための運用上の指示であって、不変式ではない**。衝突しないことを実測で示せる範囲なら、レーン指示より「Issue が着地する」ことを優先してよい — という整理をここに残す。逆に言えば、実測なしの「たぶん衝突しない」では例外にしない。#726 は PR #752 として着地済み。
