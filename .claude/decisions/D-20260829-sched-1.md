# D-20260829-sched-1: #1173 のグループをどこに保存し、フィルタの述語をどう定義するか

## 背景

#1173 は「Calendar ヘッダーの歯車をタグフィルタに置換し、既存タグのマルチセレクトを **Group** として保存できるようにして、カレンダー作成機能を完全代替する」ことを求めている。Issue 本文が **「Group の永続化方式（既存 calendars テーブルの流用 or 新規）は実装前に設計を 1 段挟むこと」** と明示しており、そこが唯一の未確定点だった。あわせて、述語（複数タグをどう合成するか）は Issue が触れていないため実装側の裁定になる。

実測した前提（2026-08-29・Supabase 本番）:

- `calendars` は「**1 つの life-tag への保存済みビュー**」でしかない（`CalendarNode = { id, title, tagId, order, ... }`）。本番 1 行
- **`wiki_tag_groups` + `wiki_tag_group_assignments` が既に存在し、どちらも 0 行・コードからの参照ゼロ**（migration 0008 tables 10/11）。RLS 4 ポリシー付与済み・`supabase_realtime` publication 加入済み・`SyncContext.REALTIME_TABLES` に登録済み。**「名前の付いたタグの集合」という意味論が Group と完全一致する**
- DDL は 🛑 ユーザー `supabase db push` ゲート（CLAUDE.md §7.3）。新規テーブルを切ると、コードが merge されても push まで機能が**死んだまま**になる

## 選択肢と裁定

- **A: `wiki_tag_groups` + `wiki_tag_group_assignments` を流用（採用）** — DDL ゼロで merge 直後から動く。親 + join の正しいモデルもそのまま手に入るので、「DDL を避けた代償にモデルが歪む」というトレードオフが発生しない
- B: 新規 `schedule_groups` テーブル — モデルは最もきれいだが、push まで機能が死ぬ。`calendars` の DROP まで含めると `syncRealtimeTables.test.ts` に drop 構文パーサを足す必要も出る（0017 の publication 配列に `calendars` が残るため union 比較だけでは表現できない）
- C: `calendars` 流用（同じ title を持つ N 行を 1 グループとみなす） — DDL ゼロだが group の同一性が文字列になり、rename が非原子・安定 id なし・同名グループ不可。A が同じ対価なしでこれを全部買い戻す

### 同時に確定した 4 点

1. **述語は UNION（OR）**。タグを 2 つ目に足す行為が「それも見せて」と読めるため。AND だと life-tag は 1 アイテム 1 個が普通なのでほぼ空になる。かつ `|tagIds| = 1` のとき現行の 1 タグ挙動に厳密に退化するので、#468 で固定した既存テストがそのまま真であり続ける
2. **保存されるのは「定義」だけで、適用中の選択は揮発**。フィルタ状態を復元すると、大半が欠けたグリッドの空きスロットに次の予定を入れてしまう（`useScheduleGridFilters` の既存注記と同じ理由）
3. **タグが 1 つでも生きていればグループは提供し続ける**。soft-delete されたタグ id だけを per-tag で落とす。全滅したグループだけをチップ列から外す（常にグリッドを空にするチップは「バグ」と読まれる）
4. **`public.calendars` は退役-in-place**（DROP しない）。`REALTIME_TABLES` に残したまま `schedule` ドメインへ再ルートすることで、`syncRealtimeTables.test.ts` の publication 突合と本数カウントが無改変で緑のままになる。`routine_groups` が #352 以降取っている形と同じ

## 波及

- 新ドメイン `tagGroups` を `SYNC_DOMAINS` に追加（TypeScript のみ・DDL なし）。`tags` に相乗りさせない理由は #993 の逆向き: `useWikiTagsUnifiedAPI` は `tags` bump ごとに bulk 3 本を引き直すので、グループの保存・改名のたびにタグ graph 全体を再取得することになる
- `CalendarProvider` / `useCalendarsAPI` / `SupabaseCalendarsService` / `calendarMapper` / `types/calendar.ts` / `CalendarView` は退役。`applyCalendarFilter` / `applyCalendarLens` と `CalendarLensRow` は**名前ごと存続**（「Calendar タブのレンズ」であって「calendars 台帳のレンズ」ではないため）
- `public.calendars` の DROP は別 PR（🛑 push ゲート）。必要作業は outbox に申し送り済み
