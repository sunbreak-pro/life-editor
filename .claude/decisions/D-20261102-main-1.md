# D-20261102-main-1: chat-main の merge をスキルでまとめ、merge の確認を自動で通す

## 背景

レーンを並列に回すと open PR が 10 本を超える。1 本ずつ確認ダイアログを押して merge するうちに、後の PR が main と衝突し、直し方を各レーンへ手で伝える手間が毎回かかっていた（2026-11-02 時点で open 13 本、うち衝突 3 本）。

## 裁定

こうだいさんの直接依頼（2026-11-02、dotfiles のセッション）で次のように決めた。この決定を入れた PR の merge をもって承認とする。

- chat-main で `merge-round` スキルを起動したら、その回の事前確認（CI・衝突・レーンの作業状態・依存・マイグレーション）を通った PR だけを、`gh pr merge <n> -R sunbreak-pro/life-editor --squash` で確認なしに merge する。
- 作業レーン（worktree）からの `gh pr merge` は `hooks/merge-gate.mjs` が deny する。chat-main でも回の外や形の違う merge は従来どおり確認を出す。
- 衝突した PR と CI が赤い PR は、レーンごとの `/goal` 指示文にまとめて出す。モデルは衝突したファイルの種類で決める。
- マイグレーションを含む PR は回に入れない。db push との順番はこうだいさんが決める。
- 戻すときは revert の PR を作り、それも merge-round で merge する。main の書き換え（reset・force push）はしない。

## 置き換えたもの

D-20260804-main-2 の「`permissions.ask` に `Bash(gh pr merge*)` を入れて P-001 を機械で担保する」を、hook による振り分けに置き換えた。ask を残すと hook の allow が効かないためです（Claude Code の仕様では、ask ルールは hook が allow を返しても確認を出す）。
