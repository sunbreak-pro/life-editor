# D-20260811-sched-1: #625 Event → Todo で日付・時間帯を Todo のチップスロットへ引き継ぐか（D-20260810-sched-3 の緩和提案）

## 背景

（キュー原文 = `comm/decisions/chat-schedule-refine.md`）

D-20260810-sched-3（= A: 時刻・終日・繰り返しは破棄）の前提は「Todo には時刻に対応する行が無い」だったが、実装中の実測で **`tasks_payload` は `scheduled_at` / `scheduled_end_at` / `is_all_day` を持っている**（task チップ = カレンダーに Todo を配置する機能の行）と分かった。前提が変わったので緩和案を提示する。現実装（PR #684）は裁定どおり破棄で、逆方向（Todo → Event）はスロットを引き継ぐため往復非対称。

## 選択肢と裁定

- A: 現状維持（破棄）。ダイアログは「日付・時刻・繰り返し設定は失われます」（却下 — 裁定どおりで実装済みだが、往復非対称が残る。Todo→Event は場所を保つのに Event→Todo は消える）
- B: **日付・時間帯を task チップスロットへ引き継ぐ**（**採用** — ユーザー回答 2026-08-12）。8/20 10:00 の予定は 8/20 10:00 に配置済みの Todo チップになる。繰り返しは引き続き破棄
  - 利点: カレンダー上の見た目がほぼ変わらず「性質だけ変わる」。失うものが繰り返しだけになりダイアログも短くなる
  - 欠点: D-20260810-sched-3 の supersede が要る。「Todo にしたのにカレンダーに残っている」を意外に感じる可能性

## 波及

- D-20260810-sched-3 を supersede（双方向リンク済み）。破棄されるのは繰り返し設定のみになり、確認ダイアログの文面も要更新
- 実装は Issue #739 として起票済み
