# D-20260923-main-1: 移行 SSOT の Phase 5「完成」条件をどう書き換えるか

## 背景

（キューを経由せず、2026-09-23 の棚卸し報告書 `docs/reports/2026-09-23-product-audit.html` の「次に判断が要る点」としてチャットで問い、回答「かきかえて」を得た。以下は報告書とチャットから再構成した）

- 移行 SSOT の Phase 5 完了判定 8 条件のうち、2026-09-23 時点で達成済みは「Web URL 公開」と「旧 `frontend/` 依存ゼロ」の 2 つだけである
- 未達のうち 3 つは条件そのものが現状と食い違っている:
  1. 「electron-updater で auto-update が GitHub Releases から流れる」は、`desktop/src/main/index.ts:786-797` が「未署名では有効化しない」雛形で止まっており、**$0 厳守（署名しない）と両立しない**
  2. 「terminal-division から MCP 経由で Todos 操作」は Terminal 退役（D-20260705-main-1）後に再定義する約束のまま。Desktop 殻の起動導線（#1211）と Remote MCP（D-20260909-mcp-mobile-1）は着地済みで、条件に反映されていない
  3. Phase 4（Capacitor ネイティブ殻）は全項目未チェックで、完成条件に含めるかが書かれていない。スマホの主導線は公開 Web URL（D-20260807-main-1）で、モバイル単独起動は Non-Goal
- ほかに `:215`「認証ありの公開配布は Non-goal」がサインアップ開放（D-20260829-main-1）と食い違う

## 選択肢と裁定

- A: 条件を現状に合わせて書き換える（**採用** — ユーザー回答 2026-09-23「かきかえて」）。内訳は chat-main の自裁:
  - 自動更新は完成条件から外し、「完成後の判断」表へ「署名と同時」の条件付きで移す
  - MCP の条件は「Desktop 殻から `claude` を起動して stdio MCP で Todo を操作できる（#1211 着地済み）」+「Remote MCP をスマホの Claude アプリから 1 本成功させる（計画書 2026-09-09 の AC）」の 2 本に置き換える
  - Phase 4 は完成条件から外す。ネイティブ殻は「完成後・任意」とし、Phase 4 の節にその旨を書く
  - 「認証ありの公開配布スケール」の Non-goal は「マルチテナントと大規模スケール」に絞り、サインアップ開放との矛盾を消す
- B: 署名を入れて自動更新を条件のまま維持する（却下 — Apple Developer Program / Windows 証明書の費用が要り、$0 厳守に反する）
- C: Phase 4 を完成条件に含める（却下 — 実機配布は Apple Developer 加入が前提で「完成後の判断」と矛盾する。シミュレータ起動だけを条件にしても利用者に届く価値が無い）

## 却下案が復活する条件

- B: 配布先が未署名の警告で詰まり、有料化（署名）をこうだいさんが裁定したとき。そのときは自動更新も同時に条件へ戻す
- C: Apple Developer Program に加入し、友達 iOS 配布を始めるとき
