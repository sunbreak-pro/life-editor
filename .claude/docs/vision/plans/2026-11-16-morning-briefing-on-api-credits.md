# Plan: life-editor の朝刊を、毎月の API クレジットで毎朝自動で書く

- **Task**: 毎朝、life-editor の今日の予定と Todo、ニュース、学びの 1 問をまとめ、朝刊として書き込む
- **Project**: life-editor（`C:/Users/user/orca/life-editor`）
- **計画書**: 2026-11-16 に claude-dotfiles の `claude/docs/plans/` から、この置き場へ移しました
- **元になる調査**: `claude/docs/reports/2026-11-16-ultra-api-credit-uses.html`（発行先は https://claude.ai/artifact/2iTZmJP18kTE7PnzuDyHP4）
- **作業の大きさ**: 中くらい。1〜2 セッションの見込みで、PR は 1 本です

## Context

### 何のための計画か

Ultra プランには、毎月 200 ドルの API クレジットが付きます。API クレジットは、自作のプログラムから Claude を呼ぶための利用枠で、対話型の Claude Code が使うプランの枠とは別の残高です。使い残しは繰り越せません。こうだいさんは 2026-11-16 に、最初の使い方として「毎朝のまとめ」を選びました。

この計画は、life-editor の朝刊（1 日を始める画面に出る、今日のフォーカスの 1 行と AI のコメント）を、毎朝スクリプトが自動で書く仕組みを作ります。費用はクレジットから払います。

### いま起きていること

2026-11-16 に確かめた事実です。

- **朝刊は、いま誰も自動で書いていません。** life-editor の「今日の文脈」を返す道具（MCP の `get_today_context`）は、今日の `hasBriefing` を `false`、直近の日（2026-11-13）の `morningComment` を `null` と返しました。
- **朝刊を書く口は、すでにあります。** MCP の `write_briefing` が、フォーカスの 1 行と、コメントの段落を受け取ります。材料は `get_today_context` の 1 回の呼び出しでそろいます（今日の予定、持ち越しの Todo、直近 3 日の夕刊、年・月・週の目標、今日の記録）。
- **定時の無人の実行は 4 本あり、どれもプランのログインで動いています。** Windows のタスクは `ClaudeHarness-Monthly`・`LifeEditor-Digest`・`LifeEditor-NightSafe`・`pdca-harness-run` です。`LifeEditor-Digest` は開発の進み具合のまとめで、生活の朝刊ではありません。life-editor の `.claude/automation/routine-morning.md` は 2026-08-06 に退役しています。
- **MCP が未登録でも、スクリプトから life-editor を呼べます。** ユーザー環境変数 `LIFE_EDITOR_*` と `LIFE_EDITOR_MCP_ENTRY` が設定済みで、`node <entry>` に JSON-RPC を流せば動きます。`claude/skills/life-editor-note/scripts/le-note.mjs` が、この形で Note を作っています。
- **料金は公式の表で確かめました。** Sonnet 5.5 は 100 万トークンあたり入力 2 ドル・出力 10 ドル、Haiku 5.5 は入力 0.10 ドル・出力 0.50 ドルです。Web 検索は 1,000 回で 10 ドルです。1 回あたり入力 2 万・出力 2 千トークンなら、Sonnet 5.5 で月 1.80 ドルです（推定）。毎朝 5 回検索すると、月 1.50 ドルが加わります（計算）。

### 制約

- **API キーを、ユーザー環境変数に置きません。** 環境変数 `ANTHROPIC_API_KEY` は、プランのログインより優先されます。常設すると、ふだんの対話型の Claude Code と、上の 4 本の無人の実行まで API 払いになります。
- **こうだいさんが書いた朝刊を上書きしません。** `hasBriefing` が `true` の日と、鍵のかかった日は、何も書かずに終わります。
- **生活の記録を、Anthropic の API へ送ります。** 予定と Todo と夕刊の文が、API の入力になります。claude.ai の life-editor の接続と同じ送り先です。保持の決まりは 2026-11-16 に公式の文書で確かめました。標準の API は、入力と出力をサーバーから 30 日以内に削除します（Privacy Center、2026-07-01 更新）。Sonnet 5.5 は、30 日の保持が必須のモデル（Fable と Mythos）に挙がっていません。Web 検索の道具は Zero Data Retention の対象ですが、動的フィルタリング（検索の途中でコードを動かす既定の動き）は対象外です。この実装は動的フィルタリングを切ります（`allowed_callers: ["direct"]`）。学習への利用の既定は、公式の文書に書かれていた範囲では確認できていません。Ultra のクレジットで呼んでも、保持の扱いが変わる記述は見つかりませんでした。
- **PC が起きていないと動きません。** タスクは、スリープを解除して動かす設定にします。電源が切れている日は、朝刊が出ません。

### Non-goals

- life-editor のアプリのコード（朝刊の画面、MCP の道具）の変更。
- 夕刊の自動化。
- ほかの 4 本の無人の実行を、API キーへ切り替えること。
- Claude Managed Agents（Anthropic 側のサーバーで動くエージェント）への移行。下の「検討した代替案」に、見直す条件を書きます。

### 設計の方針

- **エージェントを使わず、スクリプトが API を 1 回だけ呼びます。** 材料を集めるのも、書き込むのもスクリプトです。Claude は文章にするだけなので、ファイルやコマンドに触る許可が要りません。月次の「こうだいさん向けの 1 枚」と同じ考え方です。
- **流れは 4 段です。** 1 つ目に、スクリプトが `get_today_context` で材料を取ります。2 つ目に、Claude API（Messages API）を、サーバー側の Web 検索の道具を付けて 1 回呼び、決まった形の JSON を受け取ります。3 つ目に、スクリプトが JSON を検査します（項目の有無、文字数、URL の形）。4 つ目に、`write_briefing` で書き込みます。
- **朝刊の中身は 4 つです。** フォーカスの 1 行、今日の予定と持ち越しの Todo から選んだ「今日これだけは」の 1 段落、ニュースを 3 件まで（題と 1 文と URL）、学びの 1 問です。
- **話題と学びの題材は、設定ファイルに書きます。** 最初の値は、ニュースが「Claude Code と AI の開発の道具」、学びが「秘書検定 2 級」です。年の目標「秘書検定2級に合格する」が、life-editor にあるためです。
- **API キーは、暗号化したファイルに置きます。** Windows の DPAPI（ログインしている利用者だけが復号できる、Windows の暗号化の仕組み）で暗号化し、`%LOCALAPPDATA%\life-briefing\` に置きます。起動役が復号して、子のプロセスの環境にだけ渡します。
- **使いすぎは、3 か所で止めます。** Console の作業場所（workspace）の月の上限を 10 ドルにします。スクリプトは、1 回の出力の上限と、Web 検索の回数の上限を API に渡します。1 日に 2 回以上は書きません。

### こうだいさんに決めてもらう点

どの点にも仮定を置いてあり、答えが無くても Step 1 から進められます。

**ニュースの話題と、学びの題材。**

- 何が起きているか: 設定ファイルの最初の値を、「Claude Code と AI の開発の道具」と「秘書検定 2 級」に仮に置いています。
- なぜ決める必要があるか: 話題が合わないと、毎朝読まない段落が増え、朝刊そのものを読まなくなります。
- 選ぶと何が起きるか: 仮の値のままなら、すぐ動かせます。別の話題にするなら、設定ファイルの 2 行を書き換えるだけです。学びの 1 問を外すこともできます。
- 推奨と根拠: 仮の値で 1 週間動かし、読まなかった段落を外すことを推奨します。実物を読んでから決めるほうが、いま考えるより確かなためです。

**動かす時刻。**

- 何が起きているか: 06:00 に予定（ワンパンマンチャレンジ）があるので、05:30 に仮に置いています。
- なぜ決める必要があるか: 起きる前に朝刊ができていないと、朝に読めません。早すぎると、PC のスリープの解除が増えます。
- 選ぶと何が起きるか: 05:30 なら、06:00 の予定の前に読めます。ほかの時刻にするなら、タスクの登録の 1 行を変えます。
- 推奨と根拠: 05:30 を推奨します。いちばん早い予定の 30 分前で、実行は 1 分かからない見込みのためです（推定）。

## 検討した代替案

| 案 | 採否 | 採らない理由 | 見直す条件 |
| --- | --- | --- | --- |
| スクリプトが Claude API を 1 回呼ぶ | 採る | — | — |
| API キーを渡した `claude -p` に書かせる | 採らない | ファイルとコマンドの許可を絞る仕掛けが要り、1 回の費用も増える | 材料集めに、判断の要る複数の手順が出てきたとき |
| Claude Managed Agents の定時実行 | 採らない | life-editor へのつなぎ方と認証が未確認で、試験提供のため | 手元の版が 2 週間動き、PC が切れていて朝刊が出ない日が週 2 日を超えたとき |
| 既存の `LifeEditor-Digest` に足す | 採らない | 開発のまとめと生活の朝刊は読み手の場面が違い、あちらはプランのログインで動く | 見直しません |
| API キーをユーザー環境変数に置く | 採らない | 対話型の Claude Code と、ほかの無人の実行が API 払いになる | 見直しません |

2026-11-16 に、最初の使い方を選択式で聞きました。選択肢は「毎朝のまとめ」「無人の開発ループの切り替え」「既製アプリから」「今は使わない」で、こうだいさんの答えは「毎朝のまとめ」です。報告書では `claude -p` を使う形で書きましたが、既存の道具を調べた結果、API を直接呼ぶ形のほうが小さく安全だと分かったので、この計画で改めます。
