## 1. 分類の定義

- **Full**: デスクトップと同等の全機能
- **Consumption**: 閲覧が主。完了トグルや★のような**その場で完結する 1 タップ更新は含む**（フォーム相当の詳細編集は不可）。2026-08-12 ユーザー確定 [`D-20260810-mobile-2`](../../decisions/D-20260810-mobile-2.md) = A で、実装ではなく**語のほう**を実態に寄せた（旧定義 =「閲覧・確認のみ（編集不可）」）
- **Quick capture**: 素早い新規作成・簡易入力のみ（詳細編集は不可）
- **省略**: モバイルで非表示 / 非提供

## 2. 実装フェーズの方針（2026-07-25 ユーザー確定）

目標スコープ（下表「目標」列）は確定。ただし実装は段階的に進める。

- **Phase 1**: 各機能を簡潔に実装し、モバイル全体の**方向性（UX の一貫性）を揃える**ことを優先する。重い機能（詳細編集等）はこの段階では現状のまま据え置く。
- **Phase 2**: 大枠（Phase 1）が固まった後、詳細編集・Notes 編集拡充・Routines 閲覧・Undo/Redo・コマンド検索などを**アップデートとして追加**する。

## 3. 前提（実測で判明した SSOT の実態）

- セクション一覧は `shared/src/sections.ts:69-132` の `SECTIONS` が正（個数はコードを数える — 数値の非複製原則）
- `SectionDef` に「mobile 可視 boolean」は無い。全セクションが `mobileOrder` を持ち、モバイルのボトムバー（固定4 + More）から**全て到達可能**（`sections.ts:148` `MOBILE_SECTIONS`）。**モバイルで削られるのはセクション単位ではなく「各セクション内の機能」**（Issue #319 本文の「tasks」「database」セクションや「MOBILE_SECTIONS の取捨」は実態と不一致。database セクションは存在せず、tasks は #411 で Schedule の 2 つ目のタブになり、#1153 でそのタブごと退役して同セクションの右サイドバーのタブになった（Schedule にセクション内タブは無い）。Materials のタブは notes / daily の 2 つ = `web/src/hooks/useShellNavigation.ts:23`）
- レスポンシブ判定は単一ブレークポイント 768px（`shared/src/components/AppShell.tsx:147` の既定 `wideQuery = "(min-width: 768px)"` → `:153` `useMediaQuery(wideQuery, true)`）。各画面が個別に `isWide` を読む
- モバイルのヘッダー行（`header` prop）は narrow で描画されない（`AppShell.tsx` wide 分岐のみ）→ ヘッダーに載る機能はモバイルで軒並み消える
