# 環境音プリセット 5 本の実測（#1793 の切り分け）

> 2026-09-21 / work-refine / Issue #1793「環境音をオンにするとホワイトノイズ的な雑音が重なって聞こえる」の仮説 A（音源）と仮説 B（再生経路）を分けるための実測記録。

## 結論

**仮説 A（音源側）です。5 本とも 320 kbps / 48 kHz を名乗っていますが、中身は 16.2 kHz で帯域が切れた素材でした。** 18 kHz より上は -127 dB 以下、つまり何も入っていません。素の 320 kbps エンコードなら 20 kHz 付近まで残るので、元素材が低ビットレートの圧縮音源か 32 kHz の音源です。看板だけ 320 kbps に貼り替えた状態にあたります。

あわせて**ループの継ぎ目に 39〜139 ms の無音**が入ることも測れました。5 本とも Xing / LAME のギャップレスタグを持たず、波形の両端に無音が焼き込まれています。`el.loop = true`（`shared/src/context/AudioContext.tsx:202`）は末尾の無音と先頭の無音を続けて鳴らすので、1 周ごとに音が途切れます。wind は 25.8 秒に 1 回、fire は 43.8 秒に 1 回です。

音源が汚れている以上、Issue の判断ルール（「音源がきれいなときだけ再生経路を書き換える」）に従い **`AudioContext.tsx` は書き換えていません**。直し方は音源の差し替えです。

## 測り方

公開バケット `sounds` から `rain / wind / ocean / birds / fire` の 5 本と `complete.mp3` を直接ダウンロードし、Node で MP3 をデコードして PCM を解析しました。フレームヘッダと Xing / LAME タグは生のバイト列から読んでいます。スペクトルは Hann 窓 4096 点の FFT で、時間方向にパーセンタイルを取りました。再現手順は末尾に置きます。

5 本が同じ 16.25 kHz で落ちている点が決め手です。別々に録った素材が偶然同じ位置で切れることはありません。共通の工程（低ビットレートの MP3 を経由した、または 32 kHz の素材を 48 kHz に伸ばした）を通っています。

## 測定で確定しなかったこと

**「サーッ」が符号化ノイズだ、とまでは測定では言い切れません。** 帯域ごとに時間方向の 5 パーセンタイル（常に出ている量）と中央値を比べたところ、差は全帯域で 11〜13 dB とほぼ一定でした。広帯域ノイズの periodogram はもともとこのくらいばらつくので、**素材の上に乗った一定のヒスの床は検出できませんでした**。聞こえている雑音の正体を音として確かめるのは chat-main の実機確認の担当です。

実機で最初に見てほしい点が 1 つあります。**5 プリセットは独立した `Audio` element で、同時に何本でも鳴らせます**（`shared/src/context/AudioContext.tsx:207-224`）。2 本以上オンになっていれば広帯域音が足し合わさって白色雑音に近づきます。「重なって聞こえる」という症状はこの状態とも一致するので、ミキサーで 1 本だけオンにした状態と聞き比べてください。

## 音源を差し替えるときの条件

1. **非圧縮の素材から 1 回だけエンコードする。** 既存のように、すでに圧縮された音を 320 kbps で包み直さない。
2. **20 kHz 付近まで帯域を残す。** 16 kHz にブリックウォールが立っていたら、それは低ビットレート素材の再利用です。
3. **両端の無音を削り、ループ点で波形をつなぐ。** 巻き戻しの空白は無音そのものが原因なので、ここを切るのが必須です。継ぎ目はクロスフェードで滑らかにします。
4. **1 本 60 秒以上にする。** 継ぎ目の回数を減らせます。いまの wind は 25.8 秒で、1 時間に 140 回継ぎ目が来ます。
5. MP3 のギャップレスタグ（Xing / LAME）を残すかどうかは副次的です。`HTMLAudioElement` の `loop` はタグを尊重しない実装が多いため、3 の「無音を削る」が本筋になります。

## 再現手順

```bash
BASE=https://<project>.supabase.co/storage/v1/object/public/sounds
for f in rain wind ocean birds fire complete; do curl -sSo "$f.mp3" "$BASE/$f.mp3"; done
npm install mpg123-decoder
node analyze.mjs .   # 表 1〜3
node floor.mjs .     # 帯域ごとのパーセンタイルとブリックウォール
```

`analyze.mjs` は MP3 フレームヘッダと Xing / LAME タグを生バイトで読み、デコードした PCM からピーク・RMS・両端の無音長・継ぎ目の段差を出します。`floor.mjs` は 4096 点 FFT を 4096 サンプルごとに掛け、ビンごとに時間方向の 5 / 50 / 95 パーセンタイルを取ってオクターブ帯域に畳み込みます。どちらもリポジトリには入れていません（`mpg123-decoder` を本番の依存に足さないため）。必要になったら本節の説明から組み直せます。
