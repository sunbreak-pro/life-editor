Connect は「読む場所」ではなく「つなぐ場所」にする

いまの Connect はタグで一覧するだけで、タグ編集モーダルと中身がほぼ同じです。DB を数えたら、つながり自体がほとんど作られていませんでした。磨くのは見た目より先に「つなぐ手間」です。

  • 今日から

    タグ編集を取り込む

    タグ編集モーダルを退役し、Connect の中で改名・アイコン・色・削除・一括付け外しまで済ませます。同じ一覧が 2 画面ある状態が消えます。

  • 必要になったら

    リンクは近傍リストで見せる

    リンクは全部で 4 本しかありません。まず Daily / Todo / Event からも張れるようにして、見せ方は選んだ 1 件の周り 1 歩だけにします。

  • 入れない

    力学グラフとタググループ

    グラフは 2026-08-29 に退役した判断（#1152）を覆さず、4 本の線を描くだけになります。タググループは実データ 0 件です。

いちばん効く事実: Event は 90 件あってタグが付いたものが 0 件です。Connect は「トピックから入る入口」ですが、入口の向こうに Note 以外がほとんど居ません。

提案する Connect の姿

タブを足さず、1 画面のまま中身の役割を変えます。右パネルの中身だけが「いまタグを見ているのか、アイテムを見ているのか」で入れ替わります。

LEFT

タグの棚

絞り込みとタグ一覧。行を選ぶと中央が変わり、行の上で改名・アイコン・色・削除・統合ができます。所属 0 件と未分類は末尾に分けます。

CENTER

所属アイテム

種類別のグループは今のまま。チェックで複数選べて、下に「タグを付ける / 外す / 付け替える」が出ます。行クリックは今と同じで元の画面へ飛びます。

RIGHT

内訳、または関係

タグを選んでいる間は内訳と最近の動き（今の実装）。アイテムを選ぶとその 1 件の近傍（リンク / 同じタグ / 同じ日の Daily）に切り替わり、そこからリンクを足せます。

「リンクを可視化する」はこの右パネルが担います。全体の地図は描かず、選んだ 1 件から 1 歩だけ見せる形です。地図が要るほどのリンク本数が実際に溜まったら、その時に改めて考えます。

置いた仮定

  • Event にタグが 0 件なのは UI が無いからではなく、付ける動機と手間が釣り合っていないからだと見ています（TagPicker は Event 詳細に既にあります）。
  • タグ編集モーダルの入口（サイドバーのタグボタン）は、統合後は Connect へ飛ぶ行に変えます。入口自体は残す前提です。
  • 一括操作の対象は「タグの付け外し」だけで、削除やゴミ箱送りは含めません。

未確認のこと

  • Notes のタグ見出しリストを Connect に寄せるかどうか。ノート編集中の横リストとしては別の役割がありそうで、今回は触らない前提にしています。
  • タグ統合の DDL 影響。wiki_tag_assignments の付け替えで済むか、部分 UNIQUE（同一アイテム × 同一タグ）に当たるかは未調査です。
  • Mobile でのふるまい。Connect は More の中の画面で、一括操作とその場編集を狭幅でどこまで出すかは決めていません。

次に判断が要る点

  • 統合の範囲: タグ編集モーダルを退役して Connect に一本化するか、モーダルは残して Connect 側は読み取りのままにするか。
  • リンクの置き場: 右パネルで選択アイテムの近傍として出すか、Connect の 2 つ目のタブとして別に立てるか、今回は触らず LinkPanel の横展開だけにするか。
  • ClaudeDesign に出す範囲: Desktop だけ先に出すか、Desktop と Mobile を同時に出すか。
