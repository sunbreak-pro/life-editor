#1590 に書いた原因

推測ではなく、コードを見て確かめた 2 点です。

  • desktop/src/main/index.ts:164 が titleBarStyle: "hiddenInset"。macOS ではタイトルバーが消えて信号機ボタンだけがコンテンツの左上に浮くので、画面側に左上の逃げ（余白）が要ります。その余白がありません。
  • -webkit-app-region: drag がリポジトリ全体で 0 件。窓枠を隠しているのに掴める場所を宣言していないので、ヘッダーを引っぱっても動きません。

直すときの注意として、ドラッグ領域の中のボタンには no-drag を付けないとクリックが全部ドラッグに食われる点も Issue 本文に書いてあります。

Windows のアプリ化

「アプリ化」は 3 通りに分かれます。レトルト食品に例えると、できあがった袋をもらう・自分の台所で作る・工場のラインを回して配る、の 3 つです。目的によって使う道が変わります。

1. すぐ手元で使いたい（いちばん早い）

GitHub にドラフトのリリースが 1 本あり、Windows 用インストーラがすでに乗っています（Life.Editor-0.1.0-x64-setup.exe / 84 MB）。

gh release download desktop-v0.1.0 -R sunbreak-pro/life-editor -p "*setup.exe"

落ちてきた exe をダブルクリックするだけです。署名を買っていないので、初回だけ SmartScreen が「Windows によって PC が保護されました」と止めます。詳細情報 → 実行で進めば入ります。壊れているわけではありません。

2. 自分の PC でビルドする

cd desktop
npm install
npm run build:win

成果物は desktop/release/ に出ます。先に desktop/.env へ VITE_SUPABASE_URL と VITE_SUPABASE_ANON_KEY を書いておく必要があります。この 2 つが無くてもビルドは成功してしまい、起動すると真っ白な窓が出るだけになります。ここがいちばんハマる所です。焼き込めたかは次で確かめられます。

grep -rqF "<supabase のホスト名>" desktop/out/renderer/assets/ && echo baked

3. 配布用に新しい版を出す

STEP 1

版を上げる

desktop/package.json の version を上げます。ファイル名に版が入るので、タグと一致していないと名前がズレます。

STEP 2

タグを push

git tag desktop-v0.2.0 のあと git push origin desktop-v0.2.0。GitHub 側で Windows と macOS のビルドが走ります。

STEP 3

ドラフトを公開

実機で動作を確かめてから gh release edit desktop-v0.2.0 --draft=false。公開は必ず人の手です。

タグを使わず動作確認だけしたいときは workflow_dispatch で同じビルドを回せます。リリースは作られません。手順の正本は desktop/README.md で、上の内容はそこから引いています。
