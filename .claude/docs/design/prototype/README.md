# Claude Design で今の画面を動く試作として再現する — 準備一式

この folder は、Claude Design（claude.ai/design）に今の Life Editor を「クリックして確かめられる試作」として再現させるための資料とプロンプトです。データの作成・編集・削除（保存）以外の操作は、すべて試作の上で確かめられる形を狙っています。再現ができたら、余白・文字の大きさ・配置を試作の上で微調整し、その値をコードへ戻します。

- **作った日と元のコード**: 2026-10-10、main = `85aa99b9`。デイリーと集中だけは、同じ日に merge された #2173・#2174 を反映するため main = `8fc43d8d` で撮り直しました。
- **関係する Issue**: 親 #2156（Claude Design で再現して微調整する流れ）。この一式は #2153（再現用の指示書の型）を全画面に広げたもので、#2152（説明と意図を部品集に常設する）と #2154（値をコードへ戻す手順）の前段にあたります。
- **7 月の指示書との違い**: `../briefs/*.md` は新しい画面を考えさせるための依頼文でした。この一式は今の画面を写させるためのもので、旧パレットや凍結した `_COMMON-CONTEXT.md` を使いません。

## こうだいさんの手順

1. **添付物を集める**: リポジトリ直下で次を実行します。`shots/claude-design-bundle/` に添付するものが揃います。スクリーンショットは git に入りません。

   ```bash
   bash .claude/docs/design/prototype/make-bundle.sh
   ```

2. **Claude Design で新しいプロジェクトを作る**: 「DesignSystem」の部品集を読み込む設定にします。
3. **最初の 1 通を送る**: `10-prompt-initial.md` の枠の中身を貼り、`claude-design-bundle/` の 5 ファイル（`00`〜`03` と `tokens.css`）と、下の表の「1 通目」のスクリーンショットを添付します。
4. **画面を 1 つずつ足す**: `11-prompts-follow-up.md` の A の順で、1 通に 1 画面ずつ送ります。添付するのは下の表のその画面の番号のスクリーンショットだけです。枚数が多すぎて添付できないときは、`-full` の付いた縦長の版を先に外し、次にダークを外します。
5. **確かめる**: `02-interactions.md` の表を上から試し、動かない行に印を付けます。動かない行は B の枠で直させます。
6. **出来を比べる**: Claude Code に「試作と実画面を比べて」と頼み、試作のスクリーンショット（または書き出した HTML）を渡します。Claude Code が実画面と並べてずれの表を作るので、B の枠に貼ります。
7. **微調整する**: 再現が揃ったら、C の枠か試作パネルのつまみで調整します。
8. **値を持ち帰る**: 試作パネルの「値を書き出す」で出た JSON を Claude Code に渡します（D の節）。

## 置いた仮定

- **Claude Design はリポジトリを読めない**前提で作りました。非公開リポジトリを読み込めるかは 2026-09-28 の時点で未確認です（`../../reports/2026-09-28-design-tooling.html`）。読み込めると分かったら、`01-screens.md` の実装ファイルの場所をそのまま使えます。
- **見本のデータは架空**です。実画面のスクリーンショットには本人のデータが写っています。Claude Design は本人のアカウントなので添付してよいと判断しましたが、気になる画面は添付から外してください。文章の仕様だけでも再現できるように書いてあります。
- **1 回のセッションでは写しきれない**前提です。7 月の作業と #2153 の想定どおり、比べて直すのを数回くり返します。
- **DesignSystem プロジェクトへの送信（`/design-sync`）はしていません**。部品集に説明と意図のページを常設する作業は #2152 の範囲です。
