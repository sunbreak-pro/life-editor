## 1. 画面要件ダイジェスト

- **目的 / 主ユースケース**: トピック（タグ）を入口に記録を読み、**そのトピックの手入れまでその場で終える**画面。現行は閲覧専用（`web/src/connect/ConnectScreen.tsx:1-298`）で、タグ自体の編集はアプリ全体のモーダル（`web/src/tags/TagEditorHost.tsx:1-56` → `shared/src/components/tagEdit/TagEditModal.tsx`）に分かれている。この 2 つを 1 画面に統合し、さらにアイテム間リンクの近傍表示を足す
- **表示するデータ**:
  - タグ（`wiki_tags`）= 名前 + 色 + lucide アイコン名 + 所属件数。2026-09-12 の実測で生存 14 本、うち所属 0 件が 3 本
  - アイテム（`items_meta`）= 4 種類（Todo / イベント / ノート / デイリー）。生存 150 件。内訳は イベント 90 / ノート 22 / デイリー 17 / Todo 15 / ルーティン 6
  - タグ付け状況の実測: タグが付いたアイテムは **ノート 14 / ルーティン 2 / Todo 1 / イベント 0 / デイリー 0**。未分類が 133 件で圧倒的多数
  - アイテム間リンク（`wiki_tag_connections`）= 生存 **4 本**（手動 3 / ノート本文の `[[ ]]` 由来 1）。張れる UI がノート詳細だけ（`web/src/wikitag/LinkPanel.tsx:1-735`）なのが原因
  - 種別の見せ方は既存語彙が正本（`shared/src/components/items/itemRole.ts:29-70`）: 並び順 task → event → note → daily、アイコン = CheckSquare / Clock / FileText / CalendarDays、アイコン色 = accent / info / accent-secondary / warning、ラベルは常に text-secondary
- **主要操作**:
  - 現行: タグを選ぶ / タグ名で絞り込む / 行クリックで元の画面へ飛ぶ（`ConnectScreen.tsx:270-276` → `navigateToItem({ id, role, date })`）
  - 現行（モーダル側）: タグの作成・改名・アイコン・色・削除・1 件ずつのタグ外し（`shared/src/components/tagEdit/types.ts:100-135`）。保存は明示ボタンで、未保存があると切替時に確認が出る
  - 追加: 複数選択 → 一括でタグを付ける / 外す / 別タグへ移す。タグの統合。選択アイテムの近傍（リンク / 同じタグ / 同じ日のデイリー）の閲覧とリンク追加・削除
- **Desktop / Mobile の責務分割**:
  - Desktop = 全機能（3 カラム: タグの棚 / 所属アイテム / 詳細パネル）
  - Mobile = 1 画面ずつの 3 段（タグ一覧 → タグの中身 → 近傍シート）。**落とすもの = 一括選択と一括タグ操作・タグの統合・「使われていないタグ」の折り畳みグループ**。タグ管理自体は Full を維持する（2026-08-30 #1290 のスコープ変更。narrow の入口は下部「その他」シートのクイック操作で、統合後はそこから本セクションへ飛ばす）

- **現状の課題**（デザインで直したい方向）:
  1. **同じタグ一覧が 2 画面ある**。このセクションとタグ編集モーダルで、行の形まで意図的に揃えてある（`TagHubTagRail.tsx:12-14` のコメントが明言）のに、編集できるのはモーダル側だけ
  2. **読むだけで手が出ない**。目の前に 133 件の未分類があるのに、この画面からはタグを 1 つも付けられない
  3. **イベント 90 件にタグが 0 件**。1 件ずつ詳細を開いて付ける導線しか無く、まとめて片付ける場所が無い
  4. **リンクがノートの中でしか見えない**。Todo・イベント・デイリーからは張れず、全体で 4 本しか育っていない
  5. **タグの衛生管理ができない**。検証で作った残骸（所属 0 件が 3 本・重複気味の名前）を統合する手段が無く、削除か改名しかない
  6. **右パネルの役割が薄い**。種類別内訳と「最近タグを付けたもの」だけで、320px を占める価値が出ていない
  7. 密度が一様で、**いま何を選んでいるのか**（タグなのかアイテムなのか）が画面から読み取りにくい

## 3. デザイン方針（このセッションの提案）

- **残す意匠**: 左のタグレール + 中央の種類別グループという 2 ペイン構造 / タグ行の形（glyph + 名前 + 件数チップ）/ 未分類バケツを区切り線の下に置く扱い / 種別バッジの語彙（アイコン + ラベル + 色の 3 冗長）/ 行クリックは元の画面へ飛ぶ（この画面でアイテム本体は編集しない）
- **変える意匠**:
  - タグ行にホバーで「…」メニューを出し、**改名 / アイコン / 色 / 統合 / 削除をこの画面で完結**させる（モーダルは退役）
  - 中央ヘッダに編集ブロックを折り畳みで持たせ、保存ボタンと「未保存」表示を footer ではなくブロック内に置く
  - アイテム行に**チェックボックスと選択バー**を足し、一括でタグを付ける / 外す / 移す
  - **右パネルを 2 モードにする**。タグを選んでいる間は内訳（現行）、アイテムを 1 件選ぶとそのアイテムの近傍（リンク / 同じタグ / 同じ日のデイリー）へ切り替わり、そこからリンクを足せる
  - レールの末尾に「使われていないタグ」の折り畳みグループを置き、掃除の手がかりにする
- **使う既存部品**: Button / Card / Menu（行の「…」）/ Popover（タグピッカー・リンクピッカー）/ ConfirmDialog（削除・統合）/ Toast（失敗表示）/ BottomSheet（Mobile の近傍）/ EmptyState / SkeletonList / MasterDetail の 2 枚組 / 詳細パネル（押し込み式 320px）
- **新規に必要な部品候補**（列挙のみ・実装しない）:
  - `TagHubSelectionBar`（中央下にドッキングする一括操作バー）
  - `RelationPanel`（選択アイテムの近傍 3 節 + リンク追加。ノート詳細の「関連」ポップオーバーを全 role 向けに切り出したもの）
  - `TagMergeDialog`（統合先のタグを選び、件数の移動を確認する）

タグを入口に記録を読み、**そのトピックの手入れまでその場で終える**画面です。いまは読むだけの一覧で、タグの改名や色の変更は別のモーダルに分かれています。そのモーダルを畳んでこの画面に統合し、さらに「このアイテムは何とつながっているか」を見る場所を足します。タブはありません（単画面）。

### レイアウト（左から 3 カラム + シェル）

サイドバー 240px（「つながり」が選択状態）、メイン 880px、詳細パネル 320px（開いた状態）。

メイン上部に高さ 56px のヘッダー行: 左に見出し「つながり」、その右に小さな補助テキスト「タグ 14 ／ アイテム 150」、右端に詳細パネルの開閉トグル（PanelRight・活性表示）。

**① タグの棚（幅 260px・右に 1px の border）**

- 最上部に絞り込み入力（沈んだ面の色・高さ 32px・角丸 6px・虫眼鏡アイコン・プレースホルダ「タグを絞り込む…」）
- その下がタグ行のリスト。1 行 = 左に 20px のアイコン（タグごとに lucide アイコンと色を持つ。色の指定が無いタグは text-secondary の既定アイコン）+ タグ名 + 右端に件数チップ（完全円・bg-secondary・数字は等幅）。行の高さ 38px・角丸 6px・ホバーで hover 色
- **選択中の行は accent-subtle の地**で、文字は text-primary のまま（色だけに頼らないよう、左端にアクセント色の 2px バーも添える）
- **ホバーすると件数チップの右に「…」ボタン**が現れる。押すとメニュー: 「名前を変更」「アイコンを変える」「色を変える」「別のタグへ統合…」、区切り線、「削除」（danger 色）
- リストの内容（この順で・件数は実データ）: 開発 7 / 日常・プライベート 3 / ルーティン 2 / 哲学 1 / 仕事 1 / 新人 1
- その下に 1px の区切り線を引き、**「未分類 133」**の行（既定アイコン・名前は text-secondary）。タグではないことが形で分かるように区切る
- さらに下に折り畳み行**「使われていないタグ（3）」**（右向きシェブロン・閉じた状態で描く）。掃除の手がかりとして最後に置く
- レール最下部に固定の追加行: ＋ アイコン + プレースホルダ「タグ名を入力」の入力欄 + 「追加」ボタン

**② 所属アイテム（幅 620px）**

- 上端にタグのヘッダー行（高さ 52px・下に border）: 18px のタグアイコン + タグ名「開発」（16px・太字）+ 件数「7 件」（text-tertiary）+ 右端に鉛筆アイコンボタン（ツールチップ「このタグを編集」）
- **鉛筆を押した状態も 1 枚描く**（下の「状態バリエーション」参照）
- 本体は種類別のグループ。グループ見出し = 種別バッジ（アイコン + ラベルの小チップ。地は中立色で、アイコンだけ種別色）+ その右に件数の数字。並び順は Todo → イベント → ノート → デイリー で固定
  - **Todo（2）**: 「API について学んでみる」／「Issue #1589 の動作を確認する」
  - **イベント（1）**: 「仕事」（行の右端に日付「2026-09-09」）
  - **ノート（3）**: 「ゲーム設計(chat GPT)」／「生と継承 三者評価（original-card-battle）」／「Issue 報告」
  - **デイリー（1）**: 「2026-09-10」
- アイテム行 = 左にチェックボックス（通常は非表示で、行ホバー時か 1 件以上選択中のときに現れる）+ タイトル（13px）+ 右端に補助テキスト（イベントは日付）+ ホバーで右向きシェブロン（「この行は別の画面へ移動する」という合図）
- **1 件だけクリックした行は選択状態**（accent-subtle の地 + 左端 2px のアクセントバー）になり、詳細パネルが近傍モードへ切り替わる。ダブルクリックやシェブロンのクリックで元の画面へ移動する
- **チェックで 2 件以上選ぶと、カラム下端に選択バーがドッキングする**（高さ 48px・bg-secondary・上に border・影 sm）: 左に「3 件を選択中」、右にボタン 3 つ +「選択解除」。ボタンは「タグを付ける ▾」（主ボタン = accent 地）「このタグを外す」「別のタグへ移す ▾」（いずれも枠線ボタン）。▾ のボタンはタグを検索して選ぶポップオーバーを開く（検索欄 + タグ行のリスト + 最下部に「「設計」を作成」の行）

**③ 詳細パネル（幅 320px・地色は subsidebar・上部に「詳細」ヘッダー + 閉じる X）**

中身は 2 モードです。**同じ画面の 2 枚として両方描いてください。**

- **モード A（タグを選んでいて、アイテムは未選択）**: 上にタグの見出し（アイコン + 「開発」+ 「7 件」）、次に「種類別」の小見出しと内訳リスト（種別バッジ + 件数を 4 行）、次に「最近タグを付けたもの」の小見出しと 5 行のリスト（種別アイコン + タイトル + 右端に日付）
- **モード B（アイテムを 1 件選んだ）**: 最上部に戻り行「← このタグの内訳へ」、その下に選択アイテムのカード（種別アイコン + タイトル「ゲーム設計(chat GPT)」+ 「素材で開く」のテキストボタン）。続けて 3 節:
  - 「リンク（2）」: 「生と継承への上書き（original-card-battle）」／「API について学んでみる」。各行ホバーで右端に × が出る（リンクの削除）
  - 「同じタグのアイテム（4）」: 「Issue 報告」／「生と継承 三者評価（original-card-battle）」／「仕事」／「2026-09-10」
  - 「同じ日のデイリー（1）」: 「2026-09-12」

  - 節の見出しは 11px の text-tertiary、件数は括弧つきで見出しに入れる

### 状態バリエーション（それぞれ 1 枚）

1. **通常（上記・light / dark）**: モード A とモード B をそれぞれ 1 枚
2. **タグの編集を開いた状態**: 中央ヘッダーの下に編集ブロックが開く。名前の入力欄（現在値「開発」）／「アイコン」行（現在のアイコンを四角いボタンで見せ、隣に「変更」）／「色」行（12 色のスウォッチを 2 段 6 列 + 「デフォルト」+ 「カスタム」）／ブロック右下に主ボタン「保存」と、その左に「未保存」の小さな表示／ブロック左下に danger 色のテキストボタン「タグを削除」。編集ブロックが開いている間も下のアイテム一覧は見えたまま（高さが縮む）
3. **タグ未選択**: 中央に EmptyState（Tags アイコン + 「タグを選ぶと、そこに集まったものが一覧に出ます。」）。詳細パネルは何も portal されていない空の状態
4. **空状態**: タグもアイテムも無い。レールは絞り込み入力を出さず「タグはまだありません」、中央は EmptyState（「タグもアイテムもまだありません。」+ 主ボタン「タグを追加」）
5. **ローディング**: レールと中央に骨組み（横棒のスケルトン 6 行ずつ）。詳細パネルは空
6. **エラー**: 右下に danger のトースト「タグを外せませんでした。通信を確認してください。」（他は通常状態のまま）
7. **複数選択中**: ノート 2 件と Todo 1 件にチェックが入り、中央カラムの下端に選択バーが出ている状態。バーの左に「3 件を選択中」、右に「タグを付ける ▾」（主ボタン）「このタグを外す」「別のタグへ移す ▾」「選択解除」。「タグを付ける ▾」のポップオーバーを開いた状態も同じ 1 枚に描く（検索欄 + タグ行 + 最下部に「「設計」を作成」）

### 仕上げの指定

- **キーボードのフォーカス表示**を描く: 行・ボタン・入力欄のフォーカス時は accent 色の 2px リング（要素の外側に 2px のオフセット）。マウスのホバーとは別の見え方にする
- **読み上げ名**を各要素に書き添える（デザイン注記として）: タグ行は「タグ名: N 件」、種別グループの見出しは「種類名: N 件」、件数チップ単体は読み上げ対象から外す
- パレットに無い hex を 1 つも使わない。どうしても足りない色があれば「トークン追加の提案」として画面の外に注記する

### この画面でやらないこと（描かないでください）

- アイテム本体の編集（Todo の完了チェック・本文の編集・日付の変更）。行は「読む」と「移動する」だけ
- 「今日に入れる」「予定に置く」といった配置の導線（別画面の役割）
- 全アイテムの関係を一枚に描く力学グラフ・ノードの散布図（2026-08-29 に退役した機能で、復活させません）
- タグの階層・親子・グループ分け（データとして持っていません）
